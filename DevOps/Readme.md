## 1. 서비스 구현 방향성

요즘 서비스는 통합 서비스 개발(Monolithic) 방식에서 점점 기능을 분리하여 개별 서비스 형태(Microservices)로 발전하는 추세입니다.

<img width="452" height="140" alt="마이크로서비스 구조 예시" src="https://github.com/user-attachments/assets/166c0a81-2e38-440e-ac5d-581d60b7da58" />

- 마이크로서비스: 작은 기능들을 조합하여 개별 업무 서비스로 구성
- 각 서비스는 독립적으로 개발, 배포, 확장이 가능
- 대규모 서비스에서는 유지보수성과 확장성이 향상됨

---

## 2. 모놀리식 vs 마이크로서비스

### 모놀리식(Monolithic)
- 하나의 큰 애플리케이션으로 전체 기능을 구현
- 초기 개발이 간단하고 구조가 단순함
- 서비스가 커질수록 배포와 유지보수가 어려워짐

### 마이크로서비스(Microservices)
- 기능을 작은 서비스 단위로 분리
- 각 서비스가 독립적으로 운영될 수 있음
- 팀 단위로 책임을 분배하고 빠르게 개발 가능

---

## 3. 마이크로서비스의 장단점

### 장점
- 서비스별 독립 배포 가능
- 특정 기능만 확장하여 리소스 효율적 사용
- 장애 발생 시 영향 범위를 제한할 수 있음
- 팀별 업무 분담이 용이함

### 단점
- 서비스 간 통신과 데이터 관리가 복잡함
- 운영 환경이 복잡해지고 모니터링이 중요해짐
- 테스트와 배포 흐름이 더 까다로워짐

---

## 4. 요약

모놀리식에서 마이크로서비스로 전환하는 이유는 서비스 규모가 커질수록 유지보수성과 확장성, 개발 속도를 높이기 위해서입니다. 다만, 마이크로서비스는 분산 구조의 복잡성을 동반하므로 적절한 설계와 운영 역량이 필요합니다.
