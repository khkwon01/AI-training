## 이 장에서 배우는 것

- AI 도구마다 "프로젝트 전체 지시사항"을 설정하는 파일이 따로 있다는 것
- Claude Code의 `CLAUDE.md`, Cursor의 `.cursorrules`, GitHub Copilot의 `.github/copilot-instructions.md` 차이점
- `CLAUDE.md`를 직접 작성해서 AI에게 프로젝트 맥락을 전달하는 방법
- 세 가지 작성 패턴 (프로젝트 설명형 / 규칙 열거형 / 역할 정의형)
- 초보자도 바로 쓸 수 있는 템플릿과 자주 쓰는 지시사항 예시 10개

---

## 먼저 쉬운 설명

AI에게 매번 같은 설명을 반복하고 있지는 않은가?

> "이 프로젝트는 Python 3.11을 씁니다. 주석은 한국어로 써 주세요. 테스트는 pytest로 해 주세요."

새 대화를 시작할 때마다 이런 말을 반복해야 한다면 굉장히 번거롭다. AI는 대화를 끝내면 이전 내용을 기억하지 못한다. **그렇다면 프로젝트 폴더에 "이 프로젝트의 규칙"을 적어 두면 어떨까?**

바로 그게 `CLAUDE.md`가 하는 일이다.

`CLAUDE.md` 파일을 프로젝트 루트에 두면, Claude Code는 새 대화를 시작할 때마다 이 파일을 자동으로 읽는다. Cursor는 `.cursorrules`를, GitHub Copilot은 `.github/copilot-instructions.md`를 같은 방식으로 사용한다.

한번만 써 두면 AI가 매번 그 규칙대로 답해 준다. 팀원과 함께 쓰는 프로젝트라면 같은 파일을 공유하면 되니까 팀 전체가 일관된 AI 답변을 받을 수 있다.

## 1. 도구별 프로젝트 지시사항 파일 비교

AI 코딩 도구마다 지시사항 파일의 이름과 위치가 다르다. 아래 표로 한눈에 비교해 보자.

| 항목 | Claude Code | Cursor | GitHub Copilot |
|---|---|---|---|
| **파일 이름** | `CLAUDE.md` | `.cursorrules` | `copilot-instructions.md` |
| **위치** | 프로젝트 루트 (또는 하위 폴더) | 프로젝트 루트 | `.github/` 폴더 안 |
| **형식** | Markdown | 일반 텍스트 또는 Markdown | Markdown |
| **자동 로드** | 대화 시작 시 자동 | 에디터 열 때 자동 | PR/편집 시 자동 |
| **중첩 지원** | 하위 폴더마다 별도 파일 가능 | 루트 파일 하나 | 루트 파일 하나 |
| **공개 여부** | git에 커밋 가능 | git에 커밋 가능 | git에 커밋 가능 |

**핵심 포인트:**
- 세 도구 모두 "파일 하나를 저장해 두면 AI가 자동으로 읽는다"는 원리는 같다.
- Claude Code는 하위 폴더에도 `CLAUDE.md`를 둘 수 있어서 모듈별 규칙을 따로 관리할 수 있다.
- 팀 프로젝트라면 `.github/copilot-instructions.md`는 GitHub에 올리면 팀 전체가 자동으로 쓰게 된다.

```
my-project/
├── CLAUDE.md                        ← Claude Code 전용 (루트)
├── .cursorrules                     ← Cursor 전용
├── .github/
│   └── copilot-instructions.md      ← GitHub Copilot 전용
├── src/
│   ├── CLAUDE.md                    ← Claude Code: src 폴더 전용 규칙 (선택)
│   └── main.py
└── tests/
    └── test_main.py
```

## 2. CLAUDE.md 작성 패턴 3가지

`CLAUDE.md`를 어떻게 쓰느냐에 따라 AI가 다르게 동작한다. 크게 세 가지 패턴이 있다.

### 패턴 1: 프로젝트 설명형

프로젝트가 어떤 프로젝트인지 설명하는 방식이다. 처음 시작하는 프로젝트나, 팀에 새로 들어온 사람도 쉽게 이해할 수 있도록 쓴다.

```markdown
# 프로젝트 개요

이 프로젝트는 소규모 쇼핑몰의 주문 관리 백엔드 API입니다.

## 기술 스택
- 언어: Python 3.11
- 프레임워크: FastAPI 0.110
- 데이터베이스: PostgreSQL 16 (SQLAlchemy ORM)
- 테스트: pytest + httpx

## 디렉터리 구조
- `src/api/` — FastAPI 라우터
- `src/models/` — SQLAlchemy 모델
- `src/services/` — 비즈니스 로직
- `tests/` — 테스트 코드

## 실행 방법
```bash
uvicorn src.main:app --reload
```

## 주요 제약사항
- Python 3.10 이하 문법은 사용하지 않는다
- 모든 엔드포인트는 인증 미들웨어를 통과해야 한다
```

**언제 쓰나?** 팀 프로젝트, 여러 기술이 얽혀 있는 프로젝트, 오래된 코드베이스를 AI에게 이해시킬 때.

---

### 패턴 2: 규칙 열거형

"이렇게 해라", "이렇게 하지 마라"를 목록으로 나열하는 방식이다. AI가 코드를 생성할 때 따라야 할 규칙을 명확하게 전달한다.

```markdown
# 코딩 규칙

## 반드시 지킬 것
- 모든 함수에는 타입 힌트를 붙인다
- 변수명과 함수명은 snake_case를 사용한다
- 클래스명은 PascalCase를 사용한다
- 주석과 docstring은 한국어로 작성한다
- 에러 메시지도 한국어로 작성한다

## 절대 하지 말 것
- `print()`를 디버깅 목적으로 남기지 않는다 (logging 사용)
- `except:` 처럼 예외를 무조건 잡지 않는다
- 하드코딩된 비밀번호나 API 키를 코드에 직접 넣지 않는다
- `global` 변수를 사용하지 않는다

## 테스트 규칙
- 새 기능을 만들 때는 반드시 테스트도 함께 작성한다
- 테스트 함수 이름은 `test_` 로 시작하고 무엇을 테스트하는지 명확히 쓴다
- 외부 API 호출은 mock으로 처리한다
```

**언제 쓰나?** 팀 컨벤션이 이미 정해져 있을 때, AI가 자꾸 같은 실수를 반복할 때.

---

### 패턴 3: 역할 정의형

AI에게 특정 역할을 맡기는 방식이다. "너는 X다" 형태로 AI의 페르소나와 전문성을 설정한다.

```markdown
# AI 역할 설정

당신은 이 프로젝트의 시니어 백엔드 개발자입니다.

## 당신의 역할
- 코드 리뷰 시 성능과 보안을 최우선으로 고려한다
- 초보 개발자(팀원 중 주니어가 있음)가 이해할 수 있도록 설명을 붙인다
- 제안할 때는 왜 그렇게 해야 하는지 이유도 함께 설명한다
- 불필요한 복잡도를 추가하지 않는다 (YAGNI 원칙)

## 답변 스타일
- 한국어로 답변한다
- 코드 예시는 최대한 실제 프로젝트 파일 이름을 사용한다
- 모르면 모른다고 솔직히 말하고 공식 문서 링크를 안내한다

## 우선순위
1. 보안 문제 → 즉시 경고
2. 버그 → 수정 방법 제안
3. 성능 → 개선 아이디어 제안
4. 스타일 → 권고 (강제 아님)
```

**언제 쓰나?** AI가 답변하는 방식과 톤을 통일하고 싶을 때, 특정 도메인 지식을 강조하고 싶을 때.

## 3. 초보자용 CLAUDE.md 템플릿

처음 `CLAUDE.md`를 작성하는 사람을 위한 시작점 템플릿이다. 대괄호 안의 내용을 자신의 프로젝트에 맞게 바꾸면 된다.

```markdown
# [프로젝트 이름]

## 프로젝트 소개
[이 프로젝트가 무엇을 하는 프로젝트인지 한두 문장으로 설명]

예: "이 프로젝트는 가계부 앱의 백엔드 API입니다. 수입/지출을 기록하고 월별 통계를 보여 줍니다."

## 기술 스택
- 언어: [Python 3.11 / JavaScript / TypeScript 등]
- 프레임워크: [FastAPI / Express / Django 등]
- 데이터베이스: [PostgreSQL / MySQL / SQLite 등]
- 테스트 도구: [pytest / Jest 등]

## 코딩 스타일
- 주석은 한국어로 작성한다
- 함수와 변수 이름은 영어로 작성한다 (snake_case)
- 줄 길이는 최대 88자 (Black 기본값 사용)

## 이 프로젝트에서 주의할 점
- [특별히 AI에게 알려 주고 싶은 제약사항이나 설계 결정 사항]

예: "인증은 JWT를 사용합니다. 세션 기반 인증으로 바꾸지 마세요."
예: "데이터베이스 마이그레이션은 Alembic을 사용합니다. 직접 테이블을 수정하지 마세요."

## 자주 쓰는 명령어
```bash
# 개발 서버 시작
[실행 명령어]

# 테스트 실행
[테스트 명령어]

# 의존성 설치
[설치 명령어]
```

## 도움말
막히면 `docs/` 폴더의 문서를 먼저 확인하세요.
```

아래 예시를 복사해서 자신의 `CLAUDE.md`에 붙여 넣고, 필요에 따라 수정해서 쓰면 된다.

Python 코드는 Black 포매터 기준(줄 길이 88자)을 따른다.

테스트 파일은 `tests/` 폴더에 두고, 파일명은 `test_[모듈명].py` 형식을 따른다.

API 키, 비밀번호, 토큰을 코드에 직접 하드코딩하지 않는다.

**예시 7 — 에러 처리**

예외는 구체적인 예외 클래스를 사용한다. `except Exception`은 최상위에서만 사용한다.

새 API 엔드포인트는 `src/api/` 폴더에 추가한다.

요청한 범위 밖의 코드는 수정하지 않는다.

```markdown
Python 3.10 이하에서 도입된 문법만 사용한다 (match-case 문 사용 금지).

## 5. CLAUDE.md가 실제로 어떻게 동작하는가

Claude Code가 `CLAUDE.md`를 어떻게 처리하는지 이해하면 더 잘 쓸 수 있다.

```
사용자가 Claude Code 세션 시작
           ↓
Claude Code가 현재 디렉터리에서 CLAUDE.md 탐색
           ↓
루트 CLAUDE.md 발견 → 자동으로 시스템 컨텍스트에 추가
           ↓
하위 폴더에도 CLAUDE.md 있으면 → 해당 폴더 작업 시 추가로 포함
           ↓
사용자의 질문/요청에 CLAUDE.md 내용이 함께 전달됨
```

**실제 예시:**

`CLAUDE.md` 없을 때:
```
사용자: "파일을 읽는 함수 만들어 줘"

Claude: def read_file(path):
            with open(path) as f:
                return f.read()
```

`CLAUDE.md`에 `"타입 힌트 필수, 주석 한국어"` 규칙이 있을 때:
```
사용자: "파일을 읽는 함수 만들어 줘"

Claude: def read_file(path: str) -> str:
            """파일 내용을 문자열로 반환한다."""
            with open(path, encoding="utf-8") as f:
                return f.read()
```

`CLAUDE.md` 하나로 이런 차이가 생긴다.

## 6. 하위 폴더별 CLAUDE.md 활용

Claude Code는 하위 폴더에 있는 `CLAUDE.md`도 읽는다. 폴더마다 다른 규칙이 필요할 때 유용하다.

```
my-project/
├── CLAUDE.md              ← 전체 프로젝트 규칙
├── src/
│   └── CLAUDE.md          ← src 폴더 전용 규칙
├── tests/
│   └── CLAUDE.md          ← 테스트 코드 전용 규칙
└── docs/
    └── CLAUDE.md          ← 문서 작성 전용 규칙
```

**`tests/CLAUDE.md` 예시:**
```markdown
# 테스트 코드 규칙

이 폴더는 pytest 테스트 코드만 있습니다.

## 테스트 작성 규칙
- 각 테스트 함수는 단 하나의 동작만 테스트한다
- 테스트 이름은 `test_[상황]_[기대결과]` 형식으로 쓴다
  - 예: `test_login_with_wrong_password_returns_401`
- 외부 HTTP 요청은 `respx` 라이브러리로 mock 처리한다
- 데이터베이스는 인메모리 SQLite를 사용한다 (PostgreSQL 아님)

## 픽스처 위치
공용 픽스처는 `tests/conftest.py`에 정의되어 있다.
```

## 따라 하기 실습

### 실습 1: 첫 번째 CLAUDE.md 만들기

지금 작업 중인 프로젝트(또는 연습용 폴더)에 첫 번째 `CLAUDE.md`를 만들어 보자.

**1단계 — 연습용 폴더 만들기**

```bash
mkdir ~/practice-claude-md
cd ~/practice-claude-md
git init
```

**2단계 — 기본 Python 파일 만들기**

`calculator.py` 파일을 만든다:

```python
def add(a, b):
    return a + b

def subtract(a, b):
    return a - b
```

**3단계 — CLAUDE.md 작성하기**

같은 폴더에 `CLAUDE.md` 파일을 만든다:

```markdown
# 계산기 연습 프로젝트

간단한 계산기 함수를 연습하는 프로젝트입니다.

## 규칙
- 언어: Python 3.11
- 모든 함수에 타입 힌트를 붙인다
- 주석은 한국어로 작성한다
- 0으로 나누기 등 엣지 케이스를 항상 처리한다

## 코드 예시
함수는 아래 형식을 따른다:

```python
def 함수명(매개변수: 타입) -> 반환타입:
    """한국어 설명."""
    # 구현
```
```

**4단계 — Claude Code로 확인하기**

Claude Code를 열고 다음 요청을 해 보자:

```
"calculator.py 에 곱셈과 나눗셈 함수를 추가해 줘"
```

`CLAUDE.md`가 없을 때와 있을 때 결과가 어떻게 다른지 비교해 보자. 타입 힌트와 한국어 주석이 자동으로 포함되는 것을 확인할 수 있다.

### 실습 2: 규칙 추가하고 효과 확인하기

실습 1에서 만든 `CLAUDE.md`에 규칙을 하나씩 추가하면서 AI 답변이 어떻게 달라지는지 실험해 보자.

**1단계 — 현재 상태로 질문해 보기**

Claude Code에서 물어본다:
```
"나눗셈 함수에서 0으로 나누면 어떻게 해야 해?"
```

답변을 기록해 둔다.

**2단계 — CLAUDE.md에 에러 처리 규칙 추가하기**

```markdown
## 에러 처리 규칙
- 0으로 나누는 경우 `ZeroDivisionError`를 발생시키고, 한국어 메시지를 포함한다
- 예: `raise ZeroDivisionError("0으로 나눌 수 없습니다")`
- 함수 상단에 입력값 유효성 검사를 먼저 한다
```

**3단계 — 같은 질문을 다시 해 보기**

```
"나눗셈 함수에서 0으로 나누면 어떻게 해야 해?"
```

답변이 달라졌는가? `CLAUDE.md`를 통해 AI의 답변 방향을 구체적으로 조정할 수 있다는 것을 확인할 수 있다.

**4단계 — 완성된 함수 예시**

이 실습 후 나눗셈 함수는 아래처럼 바뀌어야 한다:

```python
def divide(a: float, b: float) -> float:
    """두 수를 나눈 결과를 반환한다.

    Args:
        a: 나뉘는 수
        b: 나누는 수

    Raises:
        ZeroDivisionError: b가 0이면 발생

    Returns:
        a를 b로 나눈 결과
    """
    if b == 0:
        raise ZeroDivisionError("0으로 나눌 수 없습니다")
    return a / b
```

소규모 팀(3인)이 만드는 간단한 도서 관리 REST API입니다.
팀원 중 Python 초보가 있으므로, 코드와 설명을 이해하기 쉽게 작성합니다.

## 자주 하는 실수

| 실수 | 증상 / 에러 | 해결 방법 |
|---|---|---|
| `CLAUDE.md`가 루트가 아닌 곳에 있음 | AI가 규칙을 무시하는 것 같음 | 프로젝트 루트(`.git` 폴더와 같은 위치)에 있는지 확인 |
| 파일 이름이 다름 (`claude.md`, `CLAUDE.MD`) | AI가 파일을 읽지 않음 | 정확히 `CLAUDE.md` (대소문자 구분)로 저장 |
| 지시사항이 너무 모호함 | AI가 여전히 원치 않는 코드를 생성 | "주석은 한국어로" 대신 "모든 함수 위 docstring은 한국어로 작성" 처럼 구체적으로 |
| 서로 모순되는 규칙 작성 | AI가 혼란스러운 코드 생성 | "짧게 써라" + "자세히 설명해라" 처럼 충돌하는 규칙 제거 |
| `.cursorrules` 파일이 없어서 Cursor에서 적용 안 됨 | Cursor에서 규칙 미적용 | `CLAUDE.md`와 별도로 `.cursorrules` 파일 생성 필요 |
| 너무 긴 CLAUDE.md | AI 컨텍스트 한계 초과, 규칙 일부 무시 | 핵심 규칙만 남기고, 세부 내용은 링크로 연결 (`docs/coding-style.md` 참조) |
| 비밀 정보를 CLAUDE.md에 넣음 | API 키가 git에 공개 노출 | CLAUDE.md는 git에 올라가므로 비밀번호/키는 절대 넣지 않음 |
| 규칙을 만들고 갱신 안 함 | 옛날 규칙이 적용되어 혼란 | 기술 스택이 바뀌면 CLAUDE.md도 함께 업데이트 |
