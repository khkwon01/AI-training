## 왜 필요한가 — 같은 AI인데 결과가 왜 이렇게 다른가

AI에게 "함수 만들어줘"라고 했더니 아무 쓸모 없는 예제를 준 경험이 있을 것이다. 반면 구체적으로 설명했더니 그대로 쓸 수 있는 코드가 나온 경험도 있다.

같은 AI, 같은 기능인데 왜 결과가 다른가?

AI는 애매한 지시를 받으면 가장 평균적이고 일반적인 답을 낸다. 자동완성처럼 "가장 흔한 패턴"으로 채운다. 여기에 개인의 맥락, 제약, 형식은 없다.

구체적인 지시를 받으면 그 지시에 맞는 답을 낸다.

비유: 미용실에서 "머리 잘라주세요"라고 하면 미용사가 알아서 판단한다. "옆머리는 귀 위로, 앞머리는 눈썹 위로, 전체 길이는 3cm 잘라주세요"라고 하면 원하는 결과가 나온다.

프롬프트는 AI에게 하는 지시다. 지시가 구체적일수록 결과가 내가 원하는 것에 가까워진다.

## 1. 나쁜 프롬프트 vs 좋은 프롬프트 비교 5쌍

### 비교 1. 함수 만들기

**나쁜 프롬프트:**
```
파이썬 함수 만들어줘
```

AI가 무엇을 모르는가: 어떤 기능인지, 입력/출력이 무엇인지, 조건이 있는지, 어떤 형식인지. 결과적으로 임의의 예제 함수가 나온다.

**좋은 프롬프트:**
```
Python으로 숫자 리스트를 입력받아 평균값을 반환하는 calculate_average(numbers) 함수를 만들어줘.
- 빈 리스트가 들어오면 0을 반환해야 해
- 리스트 안에 숫자가 아닌 값이 있으면 TypeError를 발생시켜야 해
- 함수에 한국어 docstring을 포함해줘
```

AI가 정확히 알 수 있는 것: 함수명, 입력 타입, 반환값, 엣지 케이스 2가지, 형식.

---

### 비교 2. 버그 수정

**나쁜 프롬프트:**
```
오류 고쳐줘
```

AI가 모르는 것: 어떤 오류인지, 코드가 무엇인지, 어떤 상황인지.

**좋은 프롬프트:**
```
Python 코드를 실행했더니 아래 오류가 났어. 원인을 설명하고 수정 방법을 알려줘.

오류 메시지:
TypeError: 'NoneType' object is not subscriptable

오류가 난 코드:
def get_username(event):
    return event["queryStringParameters"]["name"]

event = {"queryStringParameters": None}
print(get_username(event))
```

AI가 알 수 있는 것: 오류 종류, 정확한 코드, 실행 상황.

---

### 비교 3. 코드 설명

**나쁜 프롬프트:**
```
설명해줘
```

AI가 모르는 것: 무엇을 설명하는지, 어느 수준으로 설명하는지, 어떤 형식인지.

**좋은 프롬프트:**
```
아래 Python 코드를 Python을 처음 배우는 초보자에게 설명하듯이 한 줄씩 설명해줘.
전문 용어는 쉬운 한국어로 바꿔서 설명해줘.

코드:
result = [x * 2 for x in range(10) if x % 2 == 0]
```

AI가 알 수 있는 것: 대상 독자, 설명 방식, 언어, 코드.

---

### 비교 4. 리팩토링

**나쁜 프롬프트:**
```
코드 좋게 바꿔줘
```

"좋게"가 무엇인지 모호하다. 더 빠르게? 더 짧게? 더 읽기 쉽게? 더 안전하게?

**좋은 프롬프트:**
```
아래 Python 코드를 리팩토링해줘.
목표:
1. 중복된 코드를 함수로 분리하기
2. 변수명을 의미 있게 바꾸기
3. 각 함수에 한 줄 주석 추가하기

코드 실행 결과는 동일해야 해.

[코드 붙여넣기]
```

---

### 비교 5. 테스트 작성

**나쁜 프롬프트:**
```
테스트 만들어줘
```

어떤 함수의 테스트인지, 어떤 케이스를 테스트하는지, 어떤 프레임워크인지 모른다.

**좋은 프롬프트:**
```
아래 Python 함수에 대한 pytest 테스트 코드를 작성해줘.
다음 케이스를 반드시 포함해줘:
1. 정상 입력 (숫자 리스트)
2. 빈 리스트 → 0 반환
3. None 입력 → TypeError 발생
4. 리스트에 문자열 포함 → TypeError 발생

테스트 함수 이름은 test_로 시작해야 해.

def calculate_average(numbers):
    if not numbers:
        return 0
    return sum(numbers) / len(numbers)
```

## 2. 4요소: 역할 / 목표 / 제약 / 형식

좋은 프롬프트에는 이 4가지 요소가 포함된다. 모두 필요한 건 아니다. 상황에 따라 필요한 것을 추가한다.

### 요소 1. 역할 (Role)

AI에게 특정 역할을 맡기면 그 역할에 맞는 관점으로 답변한다.

```
역할 지정 없음:
"Python 코드 설명해줘"
→ AI가 일반적인 수준으로 설명

역할 지정 있음:
"Python을 처음 배우는 학생에게 설명하듯이 설명해줘"
→ 전문 용어 없이, 쉬운 비유로 설명
```

다양한 역할 예시:

| 역할 지시 | 효과 |
|----------|------|
| "Python 초보자에게 설명하듯이" | 전문 용어 없이 쉽게 설명 |
| "시니어 Python 개발자로서 코드 리뷰해줘" | 성능, 가독성, 안전성 등 전문적 관점 |
| "면접관이라고 생각하고 질문해줘" | 핵심 개념 위주로 질문 |
| "친절한 튜터처럼 단계별로 가르쳐줘" | 순차적, 설명 위주의 답변 |

### 요소 2. 목표 (Goal)

무엇을 원하는지 구체적으로 명시한다. 동사를 구체적으로 쓴다.

| 모호한 목표 | 구체적인 목표 |
|-----------|------------|
| "코드 만들어줘" | "add_memo(text) 함수를 만들어줘" |
| "설명해줘" | "enumerate()가 하는 역할을 설명해줘" |
| "고쳐줘" | "KeyError를 방지하도록 event['name'] 접근 방식을 수정해줘" |
| "테스트 만들어줘" | "calculate_discount()에 대한 pytest 테스트 3개를 만들어줘" |

### 요소 3. 제약 (Constraint)

조건이나 제한사항을 명시한다.

```
기술적 제약:
- "외부 라이브러리 없이 표준 라이브러리만 써줘"
- "Python 3.10 이상 문법을 사용해줘"
- "재귀 없이 반복문으로 구현해줘"

결과 조건:
- "빈 리스트 입력 시 0을 반환해야 해"
- "오류 발생 시 None이 아닌 예외를 발생시켜야 해"
- "원본 리스트를 변경하면 안 돼"

형태/수준 조건:
- "초보자도 이해할 수 있게 주석을 달아줘"
- "한국어 변수명은 쓰지 말아줘"
- "함수는 20줄 이하로 유지해줘"
```

### 요소 4. 형식 (Format)

결과를 어떤 형태로 줄지 명시한다.

```
코드 형식:
- "코드 블록으로 줘"
- "함수 하나에 모든 로직을 담아줘"
- "클래스 형태로 만들어줘"

설명 형식:
- "번호 목록으로 설명해줘"
- "표로 비교해줘"
- "예시 코드 포함해서 설명해줘"

범위:
- "코드만 줘, 설명은 빼줘"
- "코드와 함께 각 줄에 주석으로 설명 달아줘"
- "3문장 이내로 요약해줘"
```

## 3. 상황별 프롬프트 패턴

### 패턴 1. 코드 작성 요청

```
[언어]로 [기능]을 하는 [함수명/클래스명]을 만들어줘.
입력: [입력값 설명]
출력: [반환값 설명]
조건:
- [조건 1]
- [조건 2]
[추가 요청: docstring 포함, 한국어 주석 등]
```

실제 예시:
```
Python으로 메모 목록에서 특정 키워드를 검색하는 search_memos(memos, keyword) 함수를 만들어줘.
입력: memos는 문자열 리스트, keyword는 검색할 문자열
출력: keyword가 포함된 메모만 담은 새 리스트
조건:
- 대소문자를 구분하지 않아야 해
- keyword가 빈 문자열이면 전체 memos를 반환해야 해
- 원본 memos 리스트를 변경하면 안 돼
함수에 한국어 docstring을 포함해줘.
```

### 패턴 2. 코드 설명 요청

```
아래 [언어] 코드를 [대상 독자]에게 설명하듯이 설명해줘.
[추가 요청: 한 줄씩 / 흐름 위주로 / 비유 포함 등]

[코드]
```

실제 예시:
```
아래 Python 코드를 Python을 처음 접하는 사람에게 설명하듯이 설명해줘.
각 줄이 무엇을 하는지 한 줄씩 한국어로 설명해줘.
전문 용어가 나오면 쉬운 말로 풀어줘.

def find_even_numbers(numbers):
    return [n for n in numbers if n % 2 == 0]
```

### 패턴 3. 버그 수정 요청

```
Python 코드 실행 중 아래 오류가 났어. 원인과 수정 방법을 알려줘.

오류 메시지:
[오류 메시지 전체]

오류가 난 코드:
[관련 코드]

[추가 컨텍스트: 어떤 상황에서 발생하는지, 어떤 입력이 들어왔는지]
```

실제 예시:
```
Python 코드 실행 중 아래 오류가 났어. 원인을 설명하고 수정된 코드를 줘.

오류 메시지:
AttributeError: 'NoneType' object has no attribute 'get'

오류가 난 코드:
def get_name(event):
    return event.get("queryStringParameters").get("name", "World")

이 함수를 event = {}로 호출했을 때 발생했어.
```

### 패턴 4. 리팩토링 요청

```
아래 [언어] 코드를 리팩토링해줘.
목표: [무엇을 개선하고 싶은가]
유지해야 할 것: 기능 동일, [기타 제약]

[코드]
```

실제 예시:
```
아래 Python 코드를 리팩토링해줘.
목표:
1. 반복되는 if-else를 줄여줘
2. 함수를 더 작은 단위로 분리해줘

코드 기능은 동일하게 유지해야 해.
변수명과 함수명은 영어로 유지해줘.

def process_memo(action, text, memos):
    if action == "add":
        memos.append(text)
        return memos
    elif action == "delete":
        if text in memos:
            memos.remove(text)
        return memos
    elif action == "list":
        return memos
    else:
        return memos
```

### 패턴 5. 테스트 작성 요청

```
아래 [언어] 함수에 대한 [프레임워크] 테스트를 작성해줘.
다음 케이스를 포함해줘:
- [케이스 1]: [예상 결과]
- [케이스 2]: [예상 결과]
- [케이스 3]: 예외 발생 케이스

[함수 코드]
```

실제 예시:
```
아래 Python 함수에 대한 pytest 테스트를 작성해줘.
다음 케이스를 포함해줘:
- 정상 입력: [1, 2, 3, 4, 5] → 3.0 반환
- 빈 리스트: [] → 0 반환
- 단일 원소: [10] → 10.0 반환
- 오류 케이스: None 입력 → TypeError 발생

def calculate_average(numbers):
    if not numbers:
        return 0
    return sum(numbers) / len(numbers)
```

## 4. 프롬프트를 개선하는 3단계

처음부터 완벽한 프롬프트를 쓸 필요는 없다. 3단계로 개선한다.

### 1단계: 구체화 — "무엇을" 명확히

```
Before: "검색 기능 만들어줘"
After:  "문자열 리스트에서 특정 키워드가 들어간 항목만 반환하는 search() 함수를 만들어줘"
```

동사를 구체적으로: 만들어줘 → "search_items(items, keyword) 함수를 만들어줘"
입력/출력을 명시: → "입력: 문자열 리스트, 출력: 필터링된 리스트"

### 2단계: 맥락 추가 — "왜, 어떤 상황"

```
Before: "search_items(items, keyword) 함수를 만들어줘"
After:  "메모 앱에서 쓸 search_items(items, keyword) 함수를 만들어줘.
         keyword가 빈 문자열이면 전체를 반환하고,
         대소문자를 구분하지 않아야 해."
```

맥락을 추가하는 방법:
- 어디서 쓰는 코드인지 (메모 앱, Lambda 함수, CLI 도구)
- 어떤 입력이 들어올 수 있는지 (빈 문자열, None, 대용량 데이터)
- 무엇을 특히 신경 써야 하는지 (성능, 가독성, 안전성)

### 3단계: 형식 지정 — "어떻게 줘"

```
Before: "search_items(items, keyword) 함수를 만들어줘.
         keyword가 빈 문자열이면 전체를 반환해야 해."
After:  "search_items(items, keyword) 함수를 만들어줘.
         keyword가 빈 문자열이면 전체를 반환해야 해.
         함수에 한국어 docstring을 포함하고,
         사용 예시(example)도 코드 블록으로 보여줘."
```

형식을 지정하는 이유:
- 바로 복붙해서 쓸 수 있는 형태로 받을 수 있다
- 설명이 길어지는 것을 방지한다
- 원하는 정보만 받을 수 있다

## 5. 이전 결과를 이어받는 대화 전략

AI와의 대화는 앞 내용을 기억한다. 한 번에 모든 것을 요청하기보다 단계적으로 쌓아가는 것이 효과적이다.

```
# 1번째: 기본 함수 만들기
Python으로 메모를 추가하는 add_memo(memos, text) 함수를 만들어줘.
memos는 리스트, text는 문자열이야. 추가된 메모 목록을 반환해야 해.

→ AI가 기본 함수를 만들어줌

# 2번째: 기능 추가
방금 만든 함수에 중복 체크를 추가해줘.
같은 내용의 메모가 이미 있으면 추가하지 않고 False를 반환하고,
성공적으로 추가하면 True를 반환하도록 수정해줘.

→ AI가 이전 코드를 기반으로 수정

# 3번째: 테스트 추가
이 함수의 pytest 테스트를 만들어줘.
성공 케이스, 중복 케이스를 각각 테스트해야 해.
```

대화를 이어갈 때 주의사항:
- AI의 이전 답변이 틀렸다면 새 대화창을 열어서 처음부터 다시 요청하는 것이 더 나을 수 있다
- 대화가 너무 길어지면 앞부분의 맥락을 잊어버리는 경우가 있다
- 중요한 코드는 새 대화에서 붙여넣기로 다시 제공하는 것이 안전하다

---

## 6. 따라 하기 실습

### 실습 1. 나쁜 프롬프트를 4요소로 개선하기 — 함수 만들기

**원본 (나쁜 프롬프트):**
```
리스트 정렬해줘
```

**4요소로 분석:**
- 역할: 없음
- 목표: 모호함 (어떤 리스트? 어떻게 정렬?)
- 제약: 없음
- 형식: 없음

**개선 과정:**

1단계 (구체화):
```
Python 리스트를 정렬하는 함수를 만들어줘
```

2단계 (맥락 추가):
```
Python 리스트를 오름차순으로 정렬하는 sort_numbers(numbers) 함수를 만들어줘.
원본 리스트는 변경하면 안 되고, 정렬된 새 리스트를 반환해야 해.
빈 리스트가 들어오면 빈 리스트를 반환해야 해.
```

3단계 (형식 지정):
```
Python 리스트를 오름차순으로 정렬하는 sort_numbers(numbers) 함수를 만들어줘.
원본 리스트는 변경하면 안 되고, 정렬된 새 리스트를 반환해야 해.
빈 리스트가 들어오면 빈 리스트를 반환해야 해.
함수에 한국어 docstring을 포함하고, 사용 예시 2개를 주석으로 달아줘.
```

AI에게 이 두 가지를 모두 실제로 보내고, 결과를 비교해보자.

---

### 실습 2. 나쁜 프롬프트를 4요소로 개선하기 — 버그 수정

**원본 (나쁜 프롬프트):**
```
코드가 안 돼. 고쳐줘.
```

**이 프롬프트의 문제:**
- 어떤 코드인지 모름
- 어떻게 "안 된다"는 것인지 모름 (오류? 잘못된 결과?)
- 어떤 입력에서 문제가 생기는지 모름

**상황:** 아래 코드가 `None` 입력에서 오류를 낸다.

```python
def first_item(items):
    return items[0]
```

**4요소로 개선:**
```
아래 Python 함수가 빈 리스트나 None을 입력했을 때 오류를 낸다.
오류 없이 안전하게 동작하도록 수정해줘.
- 빈 리스트 → None 반환
- None 입력 → None 반환
- 정상 리스트 → 첫 번째 원소 반환

def first_item(items):
    return items[0]
```

실제로 두 프롬프트를 AI에게 보내고 결과를 비교하자.

---

### 실습 3. 나쁜 프롬프트를 4요소로 개선하기 — 코드 설명

**원본 (나쁜 프롬프트):**
```
이거 설명해줘
```

**이 프롬프트의 문제:**
- "이거"가 무엇인지 코드가 없음
- 어떤 수준으로 설명해야 하는지 모름
- 어떤 형식으로 줘야 하는지 모름

**상황:** 아래 코드가 이해되지 않는다.

```python
memos = {"work": [], "personal": []}
result = {k: [m for m in v if "중요" in m] for k, v in memos.items()}
```

**4요소로 개선:**
```
아래 Python 코드를 Python을 1개월째 배우고 있는 초보자에게 설명하듯이 설명해줘.
[역할: 초보자 대상]

무엇을 하는 코드인지, 각 부분이 무슨 역할인지 알려줘.
[목표: 전체 동작 + 각 부분 설명]

딕셔너리 컴프리헨션 문법은 처음 보는 거라고 가정하고 설명해줘.
[제약: 딕셔너리 컴프리헨션 낯선 독자]

번호 목록으로 단계적으로 설명해줘.
[형식: 번호 목록]

memos = {"work": [], "personal": []}
result = {k: [m for m in v if "중요" in m] for k, v in memos.items()}
```

AI에게 원본과 개선된 프롬프트를 모두 보내고 차이를 비교하자.

## 자주 막히는 지점

### 막히는 지점 1. "프롬프트를 길게 썼는데 오히려 이상한 답이 나와요"

원인: 4요소 중 서로 모순되는 내용이 있거나, 불필요한 정보가 너무 많이 포함된 경우.

해결: 핵심 요구사항만 남기고 나머지를 줄인다. 길이보다 명확성이 중요하다.

### 막히는 지점 2. "AI가 엉뚱한 언어로 코드를 줘요"

원인: 언어를 명시하지 않았다.

해결: 항상 "Python으로" 또는 "Python 3.12 기준으로"를 명시한다.

### 막히는 지점 3. "설명이 너무 길어요. 코드만 받고 싶어요"

해결: 마지막에 "코드만 줘, 설명은 빼줘"를 추가한다.

반대로 설명이 너무 적으면 "각 줄에 한국어 주석으로 설명 달아줘"를 추가한다.

### 막히는 지점 4. "AI가 준 코드가 실제로 동작하지 않아요"

프롬프트 문제일 수 있다:
- 환경 정보가 부족 (어떤 패키지가 있는지, Lambda 환경인지 등)
- 입력 형식이 불명확 (event 딕셔너리 구조를 설명하지 않음)

해결: 실제로 어떤 데이터가 들어오는지 예시를 함께 제공한다.

```
아래 Lambda 함수에서 name 파라미터를 추출해줘.
event 형식은 다음과 같아:
{"queryStringParameters": {"name": "Mina"}, "httpMethod": "GET"}

빈 경우도 있어서 queryStringParameters가 None일 수 있어.
```

## 확인 체크리스트

- [ ] 역할, 목표, 제약, 형식 4요소를 포함한 프롬프트를 스스로 작성할 수 있는가
- [ ] 나쁜 프롬프트를 받았을 때 어떤 요소가 빠져 있는지 파악할 수 있는가
- [ ] 버그 수정 요청 시 오류 메시지와 코드를 함께 붙여넣는가
- [ ] 설명 요청 시 대상 독자(초보자/전문가)를 명시하는가
- [ ] 3단계(구체화 → 맥락 추가 → 형식 지정)로 프롬프트를 개선할 수 있는가
