## 이 장에서 배우는 것

- 코딩을 배울 때 **직접 이해해야 할 개념**과 **AI에게 맡겨도 되는 작업**을 구분하는 방법
- AI(예: Claude)가 잘하는 일과 못하는 일의 차이
- "이건 내가 직접 배워야 해" vs "이건 AI한테 물어봐도 돼"를 판단하는 기준
- AI를 도구로 활용하면서도 실력이 쌓이는 공부 방법

## 먼저 쉬운 설명

요리를 배운다고 생각해 보세요.

칼 잡는 법, 불 조절하는 법, 재료 맛 보는 법은 **직접 해봐야** 몸에 익습니다. 배달 앱에 시켜서는 절대 배울 수 없어요.

하지만 "오늘 냉장고에 남은 재료로 뭘 만들 수 있을까?"는 레시피 앱한테 물어봐도 됩니다. 그게 더 빠르고 효율적이니까요.

코딩도 똑같습니다.

변수가 뭔지, 반복문이 왜 필요한지, 에러 메시지를 어떻게 읽는지는 **직접 손으로 써보고 눈으로 확인해야** 진짜 실력이 됩니다. 하지만 "이 함수 이름이 뭐였더라?", "이 형식을 어떻게 쓰는 거지?" 같은 건 AI한테 물어보는 게 현명해요.

이 장에서는 그 경계선을 명확하게 그어볼 거예요.

## 1. 직접 배워야 하는 것들

이것들은 AI가 대신해 줄 수 없습니다. **여러분의 머릿속에 직접 들어와야** 하는 개념들이에요.

### 1-1. 코드가 실행되는 순서 (흐름 읽기)

```python
# 아래 코드를 보고 어떤 순서로 실행되는지 직접 추적해 보세요.

name = "민지"          # 1번째로 실행
print("안녕하세요!")   # 2번째로 실행
print(name)            # 3번째로 실행
```

이 코드를 처음 보는 사람이 "왜 `name`을 먼저 쓰고 `print`를 나중에 쓰나요?"라고 묻는다면, 그 답을 AI 없이 설명할 수 있어야 합니다.

### 1-2. 변수와 값의 관계

```python
score = 100
score = score + 10

print(score)   # 무엇이 출력될까요?
```

`score = score + 10`이 왜 말이 되는지, 수학 시간에 배운 등호와 뭐가 다른지 — 이걸 직접 이해하지 못하면 나중에 모든 코드가 외계어처럼 보입니다.

### 1-3. 에러 메시지 읽기

```python
# 이 코드를 실행하면 에러가 납니다.
print(이름)
```

```
NameError: name '이름' is not defined
```

이 에러가 왜 났는지, 어디를 고쳐야 하는지를 AI 없이 읽을 수 있어야 합니다. 에러 메시지는 코드가 여러분에게 보내는 편지예요. 직접 읽는 법을 배워야 합니다.

## 2. AI에게 맡겨도 되는 것들

이것들은 AI가 대신해 줘도 **여러분의 실력에 해가 없는** 작업들이에요.

### 2-1. 문법 형식 확인

```python
# "리스트에서 짝수만 골라내고 싶은데 형식이 기억 안 날 때"
# AI한테 물어보세요: "파이썬에서 리스트 컴프리헨션으로 짝수만 뽑는 방법 알려줘"

numbers = [1, 2, 3, 4, 5, 6]
even_numbers = [n for n in numbers if n % 2 == 0]

print(even_numbers)   # [2, 4, 6]
```

리스트 컴프리헨션의 **논리(짝수를 골라낸다)**는 여러분이 생각해야 합니다. 하지만 `[n for n in ...]` 이라는 **형식**은 AI한테 물어봐도 됩니다.

### 2-2. 반복적인 틀 코드 생성

```python
# "파일 읽고 쓰는 기본 코드가 매번 헷갈릴 때"
# AI가 만들어 준 코드를 보고, 각 줄이 뭘 하는지 이해하는 것이 여러분의 역할

with open("data.txt", "r", encoding="utf-8") as f:
    content = f.read()

print(content)
```

이 코드를 외울 필요는 없어요. 하지만 `open`, `read`, `with` 가 각각 무슨 역할인지는 알아야 합니다.

### 2-3. 모르는 함수 이름 찾기

```python
# "문자열을 대문자로 바꾸는 함수 이름이 뭐였더라?"
# AI한테 물어보면 됩니다.

greeting = "hello, world"
print(greeting.upper())   # "HELLO, WORLD"
```

`.upper()`라는 이름을 외우는 것보다, "문자열 변환 함수가 있다는 사실을 알고 찾을 수 있다"는 게 더 중요합니다.

## 3. 경계선을 판단하는 기준

헷갈릴 때 이 두 가지 질문을 해보세요.

### 질문 1: "이걸 모르면 다음 개념을 이해할 수 없나?"

```python
# 예시: 조건문을 모르면 아래를 이해할 수 없습니다.

age = 17

if age >= 18:
    print("성인입니다.")
else:
    print("미성년자입니다.")
```

`if`가 뭔지, `>=`가 뭔지를 모르면 이 코드가 통째로 블랙박스가 됩니다. **직접 배워야 하는 개념**입니다.

### 질문 2: "AI가 틀렸을 때 내가 알아챌 수 있나?"

```python
# AI가 이런 코드를 줬다고 가정하세요.

def 할인가_계산(가격, 할인율):
    return 가격 * 할인율   # 이게 맞는 코드일까요?

print(할인가_계산(10000, 0.1))
```

```
1000.0
```

이 함수는 **할인된 금액(1000원)**을 반환하고 있습니다. 하지만 여러분이 원한 건 **할인 후 최종 가격(9000원)**이었을 수도 있어요. AI가 준 코드가 맞는지 틀린지 판단하려면 **곱셈과 함수의 개념**을 직접 이해하고 있어야 합니다.

한 줄이라도 이해가 안 되면 AI한테 다시 물어보세요. 목표는 **전체 코드를 설명할 수 있는 상태**가 되는 것입니다.
