## 이 장에서 배우는 것

- AI와 긴 코딩 세션을 진행할 때 컨텍스트(맥락)가 왜 사라지는지 이해한다
- 대화 히스토리와 메모리의 차이를 구분한다
- `CLAUDE.md` 파일로 프로젝트 맥락을 영구 저장하는 방법을 배운다
- 긴 세션에서 AI가 길을 잃지 않도록 컨텍스트를 관리하는 패턴을 익힌다
- 세션 요약 프롬프트로 작업 흐름을 이어가는 기술을 습득한다

---

## 먼저 쉬운 설명

AI와 코딩하다 보면 이런 경험을 한 적 있지 않나요?

> "조금 전에 분명히 `auth.py` 파일 얘기했는데, AI가 갑자기 모른다고 해요..."

AI는 사람처럼 대화 전체를 무한히 기억하지 못합니다. 대화가 길어질수록 앞부분 내용이 **컨텍스트 창(context window)** 밖으로 밀려나서 AI가 "잊어버린" 것처럼 행동합니다.

이건 AI의 결함이 아니라, 설계 방식입니다. 컨텍스트는 한정된 메모장 같은 거예요.

하지만 이 문제를 **능동적으로 해결하는 패턴**이 있습니다. 이 장에서는 그 패턴들을 배웁니다.

---

## 1. 컨텍스트 창이란 무엇인가

AI는 대화를 "토큰(token)" 단위로 읽습니다. 토큰은 단어나 글자 조각이라고 생각하면 됩니다. AI가 한 번에 처리할 수 있는 토큰 수는 제한되어 있어서, 대화가 길어지면 오래된 내용이 밀려납니다.

```
[대화 시작]
  나: "프로젝트 구조는 FastAPI + PostgreSQL입니다."  ← 나중에 밀려남
  AI: "알겠습니다!"
  나: "users 테이블에 email 컬럼을 추가해 주세요."  ← 나중에 밀려남
  AI: "...코드..."

  (많은 대화...)

[지금 이 순간 AI가 보는 범위]
  ← 여기서부터만 AI가 기억함
  나: "auth 미들웨어 수정해 주세요."
  AI: "어떤 프레임워크를 쓰고 계신가요?" ← 이미 말했는데!
```

이 문제를 해결하는 첫 번째 패턴은 **프로젝트 컨텍스트를 파일에 고정**하는 것입니다.

---

## 2. CLAUDE.md 파일로 영구 컨텍스트 만들기

`CLAUDE.md`는 Claude Code가 프로젝트 폴더에서 자동으로 읽는 특별한 파일입니다. AI에게 "이 프로젝트의 설명서"를 항상 보여주는 것과 같습니다.

```markdown
# CLAUDE.md 예시 (프로젝트 루트에 저장)

## 프로젝트 개요
- 이름: 도서 관리 시스템 (BookManager)
- 스택: Python 3.12, FastAPI, PostgreSQL 15, SQLAlchemy 2.0
- 실행: `uvicorn main:app --reload`

## 디렉토리 구조
```
bookmanager/
├── main.py          # FastAPI 앱 진입점
├── models/          # SQLAlchemy 모델
│   ├── book.py
│   └── user.py
├── routers/         # API 라우터
│   ├── books.py
│   └── auth.py
└── database.py      # DB 연결 설정
```

## 코딩 규칙
- 함수 이름은 snake_case 사용
- 모든 API 응답은 Pydantic 모델로 반환
- 에러는 반드시 HTTPException으로 처리

## 현재 작업 중인 것
- [ ] JWT 인증 구현 (auth.py)
- [ ] 책 검색 기능 추가
```
```

이 파일이 있으면 AI는 새 대화를 시작해도 프로젝트 맥락을 바로 이해합니다.

## 3. 세션 요약 패턴 — 긴 대화 이어가기

작업이 길어졌을 때 새 대화창을 열어야 한다면, **세션 요약 프롬프트**를 사용하세요.

```python
# session_summary.py
# AI에게 요약을 생성하도록 요청하는 프롬프트 템플릿

SESSION_SUMMARY_PROMPT = """
지금까지 우리가 한 작업을 다음 형식으로 요약해 줘:

## 완료된 작업
- (완료된 것들)

## 현재 상태
- 마지막으로 수정한 파일: 
- 해결한 버그: 
- 남은 문제: 

## 다음 세션에서 이어받을 사람에게 전달할 컨텍스트
- 중요한 결정 사항:
- 주의해야 할 코드:
- 다음 할 일:

이 요약을 'session_context.md' 파일에 저장할 수 있는 형태로 작성해 줘.
"""
```

이 프롬프트를 AI에게 붙여넣으면, AI가 요약을 만들어 줍니다. 그 요약을 파일에 저장한 뒤, 새 대화에서 그 파일을 첨부하면 됩니다.

## 4. 앵커 메시지 패턴 — 대화 중간에 리셋하기

긴 대화 **중간에** AI가 헷갈려 하면, 앵커 메시지로 컨텍스트를 다시 고정합니다.

```
# 앵커 메시지 예시 (대화 중간에 이렇게 입력)

---
[컨텍스트 리셋]
지금부터 아래 정보를 기준으로 작업해 줘:

위 맥락에서 계속 작업해 줘.
```

## 5. 점진적 컨텍스트 로딩 패턴

파일이 많은 프로젝트에서는 한 번에 모든 것을 보여주면 오히려 AI가 혼란스러워집니다. **필요한 파일만 단계적으로** 보여주는 것이 좋습니다.

```bash
# 터미널에서 사용할 수 있는 컨텍스트 로딩 스크립트
# load_context.sh

#!/bin/bash
# 현재 작업 관련 파일만 출력해서 AI에게 붙여넣기용으로 사용

TARGET_FILE=$1

echo "=== 작업 대상 파일 ==="
cat "$TARGET_FILE"

echo ""
echo "=== 관련 모델 파일 ==="
# import 문에서 연관 파일 자동 추출
grep -h "^from\|^import" "$TARGET_FILE" | head -20

echo ""
echo "=== 최근 변경 사항 ==="
git diff HEAD~1 "$TARGET_FILE" 2>/dev/null || echo "(git 히스토리 없음)"
```

```python
# 사용 예시: routers/auth.py 작업 시 컨텍스트 로딩

# 1단계: 대상 파일만 보여주기
# load_context.sh routers/auth.py

# 2단계: AI가 추가 파일 요청하면 그때 보여주기
# "models/user.py 파일도 보여주세요" → 그때 cat models/user.py

# 3단계: 테스트 실패 시 에러 메시지와 관련 코드만 추가
# pytest tests/test_auth.py -v 2>&1 | tail -30
```

## 자주 하는 실수

| 실수 | 증상 / 에러 메시지 | 해결 방법 |
|------|-------------------|-----------|
| CLAUDE.md를 잘못된 위치에 저장 | AI가 프로젝트 정보를 모름 | 프로젝트 **루트** 폴더(`.git`과 같은 위치)에 저장 |
| 앵커 메시지 없이 계속 대화 | AI가 `"어떤 언어를 사용하나요?"` 같은 질문 반복 | 대화가 길어지면 중간에 앵커 메시지로 컨텍스트 재설정 |
| 너무 많은 파일을 한 번에 붙여넣기 | AI가 `"파일이 너무 많아서 혼란스럽습니다"` 또는 엉뚱한 파일 수정 | 관련 파일만 1~3개 단계적으로 제공 |
| 세션 요약 없이 새 대화 시작 | 이전 맥락을 처음부터 다시 설명해야 함 | 대화 끊기 전 반드시 요약 요청 후 저장 |
| CLAUDE.md를 한 번 쓰고 방치 | 프로젝트가 바뀌었는데 AI가 구버전 기준으로 답변 | 주요 변경 시마다 CLAUDE.md 업데이트 |
| 에러 메시지 없이 "안 돼요" 전달 | AI가 `"더 많은 정보가 필요합니다"` 응답 | 에러 전체 스택 트레이스를 복사해서 붙여넣기 |
