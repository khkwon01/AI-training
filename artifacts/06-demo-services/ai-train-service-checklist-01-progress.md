## 이 장에서 배우는 것

- 서비스를 만드는 전체 흐름이 어떤 단계로 이루어지는지 파악한다
- 각 단계에서 내가 무엇을 해야 하는지 체크리스트로 정리한다
- 체크리스트를 보면서 빠진 단계를 스스로 발견하고 채울 수 있다
- AI에게 요청할 때 어느 단계에 있는지 명확히 전달하는 방법을 익힌다

---

## 먼저 쉬운 설명

집을 지을 때 설계도 없이 그냥 벽돌을 쌓으면 어떻게 될까요? 중간에 방이 너무 좁아지거나, 문이 열리지 않는 위치에 달리거나, 나중에 다시 뜯어내야 하는 상황이 생깁니다.

코딩으로 서비스를 만들 때도 똑같습니다. "일단 코드부터 짜보자"고 시작하면, 나중에 "아, 이 기능을 처음에 생각했어야 했는데..."라는 상황이 반복됩니다.

**Progress checklist(진행 체크리스트)**는 내가 지금 어느 단계에 있는지 확인하는 지도입니다. 체크리스트가 있으면:

- 다음에 뭘 해야 할지 막막하지 않습니다
- AI에게 요청할 때 "나는 지금 3단계야"라고 정확히 말할 수 있습니다
- 빠뜨린 단계를 발견할 수 있습니다

---

## 1. 서비스 만들기의 전체 흐름

서비스를 만드는 과정은 크게 세 덩어리로 나눌 수 있습니다.

```
[기획] → [AI 요청] → [코드 작성 및 확인]
```

각 덩어리 안에 세부 단계가 있습니다. 아래 파일처럼 정리해 두면 언제든지 꺼내볼 수 있습니다.

```markdown
# my_service_checklist.md

## 1단계: 서비스 기획
- [ ] 서비스 이름을 정했다
- [ ] 이 서비스가 해결하는 문제를 한 문장으로 쓸 수 있다
- [ ] 주요 사용자(누가 쓰는지)를 정했다
- [ ] 꼭 있어야 할 기능 목록을 적었다 (3개 이상)
- [ ] 없어도 되는 기능과 있어야 하는 기능을 구분했다

## 2단계: AI 요청 준비
- [ ] AI에게 무엇을 만들어 달라고 할지 문장으로 써봤다
- [ ] 어떤 언어/프레임워크를 사용할지 정했다
- [ ] 입력값과 출력값이 무엇인지 정했다
- [ ] 예시 데이터를 한 가지 이상 준비했다

## 3단계: Tiny Service 코드 작성
- [ ] 가장 작은 단위로 기능 하나를 먼저 만들었다
- [ ] 만든 코드가 실제로 실행되는지 확인했다
- [ ] 에러가 났을 때 에러 메시지를 읽고 이해했다
- [ ] 기능을 하나씩 추가하면서 매번 실행해봤다
- [ ] 완성된 코드를 파일에 저장했다
```

---

## 2. 기획 단계 체크리스트 작성법

기획 단계에서 가장 중요한 것은 **"무엇을 만드는가"를 한 문장으로 쓰는 것**입니다.

아래처럼 `planning.md` 파일을 만들어 정리하세요.

```markdown
# planning.md

## 서비스 이름
할 일 알림 봇

## 한 문장 설명
사용자가 입력한 할 일 목록을 매일 아침 8시에 문자로 보내주는 서비스

## 주요 사용자
바쁜 직장인, 할 일을 자주 잊어버리는 사람

## 꼭 있어야 할 기능 (Must Have)
- 할 일 추가하기
- 할 일 목록 보기
- 매일 아침 알림 보내기

## 있으면 좋은 기능 (Nice to Have)
- 마감일 설정
- 반복 일정 추가
```

이 파일이 완성되면 기획 단계 체크리스트의 모든 항목에 체크할 수 있습니다.

---

## 3. AI 요청 단계 체크리스트 작성법

AI에게 요청할 때는 **막연하게 말하면 막연한 답이 옵니다**. 체크리스트를 채운 뒤 요청하면 훨씬 좋은 코드를 받을 수 있습니다.

```markdown
# ai_request_template.md

## AI 요청 전 체크리스트

- [ ] 언어: Python 3.11
- [ ] 무엇을 만드나: 할 일을 추가하고 목록을 출력하는 CLI 프로그램
- [ ] 입력값: 사용자가 키보드로 입력하는 텍스트
- [ ] 출력값: 화면에 번호가 붙은 할 일 목록 출력
- [ ] 예시 입력: "장보기", "운동하기"
- [ ] 예시 출력:
      1. 장보기
      2. 운동하기

## 실제 AI 요청 문장
"Python으로 할 일을 추가하고 목록을 출력하는 CLI 프로그램을 만들어줘.
사용자가 텍스트를 입력하면 목록에 추가되고,
'list'를 입력하면 번호가 붙은 목록이 출력돼야 해."
```

## 4. Tiny Service 코드 단계 체크리스트

Tiny Service는 **가장 작고 실제로 동작하는 버전**입니다. 처음부터 모든 기능을 다 만들려고 하지 마세요.

```python
# todo_tiny.py  ← 가장 작은 버전, 기능 하나만

todo_list = []

def add_todo(item):
    todo_list.append(item)
    print(f"추가됨: {item}")

def show_todos():
    if not todo_list:
        print("할 일이 없습니다.")
        return
    for i, item in enumerate(todo_list, 1):
        print(f"{i}. {item}")

# 실행 테스트
add_todo("장보기")
add_todo("운동하기")
show_todos()
```

실행 결과:
```
추가됨: 장보기
추가됨: 운동하기
1. 장보기
2. 운동하기
```

이 코드가 실제로 돌아가면 체크리스트의 "가장 작은 단위로 기능 하나를 먼저 만들었다" 항목에 체크할 수 있습니다.

### 실습 2: Tiny Service 코드에 체크리스트 연결하기

`todo_tiny.py`를 만들고 실행한 뒤, 실습 1의 체크리스트에서 코드 관련 항목에 `[x]` 표시를 하세요.

```python
# todo_tiny.py

todo_list = []

def add_todo(item):

    print(f"추가됨: {item}")

    for i, item in enumerate(todo_list, 1):
```

실행 명령어:
```bash
python todo_tiny.py
```

## 자주 하는 실수

| 실수 | 에러 메시지 또는 증상 | 해결 방법 |
|------|----------------------|-----------|
| 체크리스트 없이 바로 코딩 시작 | 나중에 기능이 뭔지 기억이 안 남 | `planning.md`를 먼저 만들고 시작 |
| AI에게 너무 막연하게 요청 | 원하는 코드가 안 나옴 | 입력값, 출력값, 언어를 명시해서 요청 |
| `python todo_tiny.py` 실행 시 파일 없음 | `python: can't open file 'todo_tiny.py': No such file or directory` | 파일이 있는 폴더에서 명령어 실행 (cd 명령어로 이동) |
| 한 번에 모든 기능 구현 시도 | 코드가 너무 길어져서 에러 위치를 모름 | 기능 하나씩 추가하고 매번 실행해서 확인 |
| `[x]` 표시 없이 체크리스트 방치 | 어디까지 했는지 다시 처음부터 확인해야 함 | 기능 하나 완성할 때마다 바로 체크 |
| `IndentationError` | `IndentationError: expected an indented block` | 함수 안의 코드는 반드시 띄어쓰기 4칸 들여쓰기 |
