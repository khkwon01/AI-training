# ai-train AWS Validation Practice 01

## 목표

배포 후 무엇을 확인해야 하는지 아주 작은 예제로 따라 해 본다.
이번 연습은 "잘 배포됐는지 한 번 확인하는 습관"을 만드는 데 초점을 둔다.

## 예시 상황

작은 Python 서비스가 아래처럼 상태를 반환한다고 가정하자.

```python
def health():
    return {"status": "ok", "message": "hello from aws"}
```

## 따라 하기 순서

### 1단계. 무엇을 배포하는지 한 줄로 적기

예:

`상태 확인용 작은 Python 서비스`

### 2단계. 배포 방식 정하기

- 아주 작은 기능이면 `serverless`
- 구조를 함께 보여주고 싶으면 `container`

이번 연습에서는 복잡한 구성을 피하기 위해  
`아주 작은 기능 -> serverless`라고 생각하고 진행하면 된다.

### 3단계. 확인할 주소 또는 방법 정하기

예:

- health 주소 열기
- 간단한 요청 보내기

### 4단계. 기대 결과 적기

예:

```text
status 값이 ok로 보여야 한다
message 값이 hello from aws로 보여야 한다
```

### 5단계. 실패 시 어디를 볼지 적기

- 로그
- 환경변수
- 최근 배포 설정

### 6단계. 워크북 칸 채우기

아래 빈칸을 직접 채워 본다.

```text
내 서비스 한 줄 설명:
________________________________

내가 확인할 주소 또는 방법:
________________________________

성공 기준:
________________________________

실패 시 첫 확인 위치:
________________________________
```

## 간단한 검증 시나리오

아래 순서대로 상상하면서 체크해 본다.

1. health 주소를 연다.
2. 응답에 `status`가 있는지 본다.
3. 값이 `ok`인지 확인한다.
4. `message`도 기대한 값인지 확인한다.
5. 틀리면 로그와 환경변수를 본다.

## 확인 체크리스트

- 무엇을 배포했는지 설명할 수 있는가
- 왜 그 방식을 골랐는가
- 성공 기준이 있는가
- 실패 시 어디를 볼지 정했는가

### 성공 체크

- 응답이 온다
- `status`가 `ok`다
- `message`가 기대한 값이다
- 내가 적은 성공 기준과 실제 결과가 맞는다

### 실패 체크

- 응답 자체가 오지 않는다
- `status`가 없거나 다른 값이다
- `message`가 비어 있거나 예상과 다르다
- 로그나 환경변수 확인 위치를 모른다
