# ai-train Module 05: AI와 Vibe Coding 이해하기

## 이 장에서 배우는 것

- vibe coding이 무엇인지
- 왜 초보자에게 매력적으로 느껴지는지
- 왜 "그대로 복사"가 아니라 "작게 요청하고 검토"가 중요한지
- AI에게 요청하고, 읽고, 수정하고, 검증하는 기본 루프

---

## 먼저 쉬운 설명

vibe coding은 사람이 코드를 처음부터 끝까지 직접 쓰기보다,
AI에게 원하는 기능을 설명하고 초안을 받아서 같이 고치는 방식이라고 생각하면 쉽다.

예를 들어:

- "메모 1개를 저장하는 Python 함수 만들어 줘"
- "이 에러를 쉽게 설명해 줘"
- "변수 이름을 초보자가 읽기 쉽게 바꿔 줘"

이런 요청을 자연어로 하고,
사람은 결과를 읽고 고치고 다시 묻는다.

핵심은 "AI가 대신 완성한다"가 아니라
"AI가 초안을 만들고 사람은 검토하고 선택한다"는 점이다.

---

## 1. 왜 초보자에게 매력적일까

- 결과를 빨리 볼 수 있다
- 빈 화면에서 무엇부터 써야 할지 막힐 때 출발점을 얻을 수 있다
- 같은 기능을 여러 방식으로 비교해 볼 수 있다
- 설명을 다시 요청할 수 있어서 혼자 공부할 때 도움이 된다

---

## 2. 왜 그대로 믿으면 위험할까

AI가 만든 코드에는 아래 문제가 섞일 수 있다.

- 기능은 비슷하지만 내가 요청한 것과 조금 다름
- 변수 이름이나 함수 이름이 이해하기 어려움
- 설명은 그럴듯하지만 실제 실행해 보면 오류가 남
- 너무 큰 구조를 한 번에 만들어 초보자가 읽지 못함

그래서 초보자 수업에서는 아래 기준이 필요하다.

1. 작은 기능만 요청하기
2. 결과를 바로 복사하지 않고 먼저 읽기
3. 실행 결과나 예시 입력으로 확인하기
4. 이해 안 되는 줄은 다시 설명받기

---

## 3. 초보자용 기본 루프

초보자는 아래 네 단계를 반복하는 방식이 가장 안전하다.

```text
작게 요청하기
  ↓
결과 읽기
  ↓
헷갈리는 부분 다시 묻기
  ↓
실행하거나 예시로 검증하기
```

이 루프를 한 번에 크게 하지 말고,
기능 1개 단위로 짧게 반복하는 것이 중요하다.

---

## 4. 약한 프롬프트와 더 좋은 프롬프트

### 너무 약한 프롬프트

```text
메모 프로그램 만들어줘.
```

문제:

- 범위가 너무 크다
- 어떤 언어인지 모른다
- 초보자 설명이 필요한지 모른다
- 어디까지 만들지 기준이 없다

### 더 좋은 프롬프트

```text
초보자를 위해 Python으로 메모 1개를 리스트에 저장하는 아주 작은 예제를 만들어줘.
함수는 1개만 만들고, 변수 이름은 읽기 쉽게 써줘.
코드 아래에 각 줄이 무슨 역할인지 쉬운 말로 설명해줘.
```

좋아진 점:

- 언어가 분명하다
- 기능이 1개로 작다
- 코드 길이를 스스로 줄이게 만든다
- 설명 수준이 명확하다

---

## 5. 실제 예: tiny service 코드에 연결하기

우리가 만드는 작은 서비스가 "메모 저장"이라면
아래처럼 요청을 작게 나누는 것이 좋다.

### 첫 요청

```text
초보자를 위해 Python으로 메모 1개를 저장하는 함수 예제를 만들어줘.
리스트와 딕셔너리를 사용하고, 코드 아래에 쉬운 설명을 붙여줘.
```

### 두 번째 요청

```text
이 코드에서 초보자가 헷갈릴 수 있는 변수 이름을 더 쉽게 바꿔줘.
기능은 바꾸지 말고 이름만 정리해줘.
```

### 세 번째 요청

```text
이 코드를 실행했을 때 어떤 값이 출력되는지 예시를 보여줘.
```

### 네 번째 요청

```text
이 기능 다음에 붙이면 좋은 아주 작은 두 번째 기능 1개만 추천해줘.
오늘 안에 만들 수 있는 수준으로 설명해줘.
```

이렇게 하면 AI가 큰 서비스를 한 번에 만드는 것이 아니라,
작은 수업 단위로 계속 이어 붙이는 도구가 된다.

## 6. 작은 worked example

아래는 tiny service 01로 이어질 수 있는 아주 짧은 예다.

### 첫 프롬프트

```text
초보자를 위해 Python으로 메모 1개를 리스트에 저장하는 함수 예제를 만들어줘.
함수는 1개만 만들고, 변수 이름은 읽기 쉽게 써줘.
코드 아래에 쉬운 설명도 붙여줘.
```

### AI 초안 예

```python
notes = []


def add_note(text):
    note = {"text": text}
    notes.append(note)
    return note


print(add_note("Python 공부 시작"))
```

### 사람이 확인할 점

- 함수가 1개인가
- 리스트와 딕셔너리가 보이는가
- 출력이 무엇인지 예상할 수 있는가
- 이름이 충분히 읽히는가

### 후속 프롬프트

```text
좋아. 이제 이 코드에 대해 예시 입력과 예상 출력을 짧게 설명해줘.
그리고 초보자가 헷갈릴 수 있는 줄을 한 줄씩 설명해줘.
```

### 검증 프롬프트

```text
이 코드를 VS Code 터미널에서 실행할 때 나와야 하는 결과를 보여줘.
```

---

## 7. 결과를 읽을 때 보는 기준

AI가 코드를 주면 바로 아래를 본다.

| 확인할 것 | 질문 |
|----------|------|
| 기능 범위 | 내가 요청한 기능 1개만 들어 있는가 |
| 이름 | 함수와 변수 이름이 읽히는가 |
| 입력과 출력 | 무엇을 넣고 무엇이 나오는지 보이는가 |
| 설명 | 코드 설명이 실제 코드와 맞는가 |
| 다음 단계 | 이걸 바탕으로 다음 작은 기능을 정할 수 있는가 |

---

## 8. 초보자용 검증 방법

코드가 길지 않아도 검증은 해야 한다.

### 가장 쉬운 검증 3가지

1. 직접 실행해 보기
2. 예시 입력과 출력 적어 보기
3. 한 줄씩 무슨 역할인지 설명해 보기

예:

```text
입력: "Python 공부 시작"
예상 결과: notes 리스트 안에 메모 1개가 들어간다
```

설명하지 못하는 줄이 있으면 AI에게 그 줄만 다시 묻는다.

---

## 9. 따라 하기 실습

### 실습 1. 작은 요청 만들기

```text
초보자를 위해 숫자 두 개를 더하는 Python 함수를 만들어줘.
함수는 1개만 만들고, 코드 아래에 쉬운 설명을 붙여줘.
```

### 실습 2. 결과 읽기

아래를 표시한다.

- 함수 이름이 이해되는가
- 입력값이 무엇인지 보이는가
- 반환값이 무엇인지 보이는가
- 설명이 코드와 맞는가

### 실습 3. 수정 요청하기

```text
이 코드에서 초보자가 헷갈릴 수 있는 줄을 더 쉽게 설명해줘.
변수 이름도 더 읽기 쉽게 바꿔줘.
```

### 실습 4. 검증 요청하기

```text
이 함수를 실행하는 예시 입력 2개와 예상 출력 2개를 보여줘.
```

---

## 10. 자주 하는 실수

- 너무 큰 프로그램을 한 번에 요청하기
- "로그인 기능, 저장, 배포까지 한 번에" 같이 범위를 크게 잡기
- 결과를 이해하지 않고 바로 복사하기
- 실행이나 예시 검증 없이 맞다고 가정하기
- AI 설명만 읽고 실제 코드는 읽지 않기

---

## 11. 확인 체크리스트

- 작은 기능 1개만 요청했는가
- 언어와 수준을 분명히 적었는가
- 결과를 읽고 이해 안 되는 줄을 표시했는가
- 다시 설명이나 이름 수정을 요청했는가
- 직접 실행 또는 예시 입력으로 확인했는가
- 다음 작은 기능을 한 줄로 정할 수 있는가
