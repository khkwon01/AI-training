## 이 장에서 배우는 것

- 서비스 아이디어를 AI가 이해할 수 있는 작은 단위로 쪼개는 방법
- "좋은 prompt"와 "나쁜 prompt"의 차이를 눈으로 비교하는 방법
- 서비스 설명 → 기능 분해 → 구현 요청 → 검토 요청 → 다음 단계 순서로 이어지는 prompt set 만들기
- 초보자가 바로 복사해서 쓸 수 있는 prompt 템플릿 패턴

---

## 먼저 쉬운 설명

AI에게 코딩을 부탁할 때 가장 흔히 하는 실수가 있어요.

> "인스타그램 같은 SNS 앱 만들어줘."

이 한 문장으로 결과가 나올까요? 나오긴 해요. 하지만 원하는 것과 전혀 다른 코드가 쏟아지거나, 중간에 AI가 길을 잃어버려요.

요리를 배우는 상황을 생각해 보세요. "오늘 저녁 코스 요리 만들어줘"라고 말하는 것과 "양파를 반달 모양으로 썰어줘"라고 말하는 것 중 어느 쪽이 더 빨리, 정확하게 결과가 나올까요?

AI 코딩도 똑같아요. **작게 쪼개면 쪼갤수록 AI는 더 잘 도와줍니다.** 이번 장에서는 그 '쪼개는 기술'을 prompt set이라는 형식으로 배워요. Prompt set은 한 번 만들어두면 비슷한 서비스를 만들 때 계속 재활용할 수 있는 prompt 모음이에요.

## 1. Prompt의 크기가 결과를 결정한다

### 나쁜 prompt vs 좋은 prompt 비교

**나쁜 prompt (너무 크다)**

```
할 일 관리 앱을 만들어줘. 할 일 추가, 삭제, 완료 체크, 날짜 정렬,
카테고리 분류, 알림 기능, 다크모드, 로그인 기능까지 다 넣어줘.
```

이 prompt의 문제점:
- AI가 어디서부터 시작해야 할지 모른다
- 기능이 서로 충돌할 수 있다
- 중간에 실수가 생겨도 어디가 잘못됐는지 찾기 어렵다
- 결과물이 나와도 내가 이해하기 어렵다

**좋은 prompt (작고 구체적이다)**

```
todo.html 파일을 새로 만들어줘.
화면에 텍스트 입력창 하나와 "추가" 버튼만 있으면 돼.
스타일은 아직 필요 없어. HTML 구조만 잡아줘.
```

이 prompt의 장점:
- 결과물이 딱 하나다 (HTML 파일)
- 내가 직접 확인할 수 있다
- 다음 단계로 연결할 수 있다

### 크기를 판단하는 기준

```
✅ 좋은 크기의 prompt 체크리스트:
- 결과물이 파일 1~2개 이하인가?
- "그리고", "또한", "그 다음에"가 1번 이하인가?
- 30분 안에 내가 결과를 검토할 수 있는가?
- 이 단계가 실패해도 되돌리기 쉬운가?
```

## 2. 5단계 Prompt Set 구조

하나의 기능을 만들 때 항상 이 5단계 순서를 따르세요.

### 단계 1: 서비스 설명 Prompt

AI에게 내가 만들려는 것의 전체 맥락을 알려주는 첫 번째 prompt예요. 이건 코드를 만들어달라는 게 아니라, **지금 우리가 함께 만들 것**을 선언하는 거예요.

```
[서비스 설명 prompt 템플릿]

나는 [서비스 이름]을 만들고 있어.
이 서비스는 [한 문장 설명]이야.
주요 사용자는 [사용자 설명]이고,
가장 중요한 기능은 [핵심 기능 1~2개]야.
지금 당장 코드를 짜지 않아도 돼. 내가 설명하는 걸 이해했다고만 알려줘.
```

**실제 예시:**

```
나는 "오늘뭐먹지" 앱을 만들고 있어.
이 서비스는 혼자 사는 사람들이 오늘 먹을 메뉴를 랜덤으로 추천받는 앱이야.
주요 사용자는 혼밥하는 직장인이고,
가장 중요한 기능은 버튼 하나로 메뉴 추천받기야.
지금 당장 코드를 짜지 않아도 돼. 내가 설명하는 걸 이해했다고만 알려줘.
```

### 단계 2: 첫 기능 분해 Prompt

서비스를 통째로 만드는 게 아니라, **오늘 만들 기능 딱 하나**를 고르고 그것도 더 작게 쪼개달라고 부탁해요.

```
[기능 분해 prompt 템플릿]

[기능 이름] 기능을 만들고 싶어.
이걸 가장 작은 단계로 쪼개줘.
각 단계는 30분 안에 만들 수 있어야 하고,
코드는 아직 쓰지 마. 단계 목록만 알려줘.
```

**실제 예시:**

```
메뉴 추천 기능을 만들고 싶어.
이걸 가장 작은 단계로 쪼개줘.
각 단계는 30분 안에 만들 수 있어야 하고,
코드는 아직 쓰지 마. 단계 목록만 알려줘.
```

**AI가 돌려주는 예시 답변:**

```
단계 1: 메뉴 목록 배열을 가진 menu.js 파일 만들기
단계 2: index.html에 "오늘의 추천" 버튼 추가하기
단계 3: 버튼 클릭 시 배열에서 랜덤 메뉴를 화면에 표시하는 함수 연결하기
단계 4: 결과가 제대로 나오는지 브라우저에서 확인하기
```

### 단계 3: 구현 요청 Prompt

분해한 단계 중 **하나만** 골라서 만들어달라고 해요. 절대 여러 단계를 한꺼번에 요청하지 마세요.

```
[구현 요청 prompt 템플릿]

[파일 이름]에 [단계 설명]을 추가해줘.
다른 기능은 아직 건드리지 마.
완성되면 어떻게 확인할 수 있는지도 알려줘.
```

**실제 예시:**

```
menu.js 파일을 새로 만들어줘.
한국 음식 메뉴 이름 10개를 담은 배열 하나만 있으면 돼.
다른 기능은 아직 건드리지 마.
완성되면 어떻게 확인할 수 있는지도 알려줘.
```

**AI가 만들어주는 예시 코드:**

```javascript
// menu.js
const menuList = [
  "김치찌개",
  "된장찌개",
  "비빔밥",
  "삼겹살",
  "순두부찌개",
  "제육볶음",
  "부대찌개",
  "갈비탕",
  "냉면",
  "떡볶이"
];
```

### 단계 4: 검토 요청 Prompt

코드가 만들어진 뒤에는 꼭 검토를 요청하세요. 특히 초보자라면 AI가 만든 코드에서 실수가 있는지 같이 확인하는 게 중요해요.

```
[검토 요청 prompt 템플릿]

방금 만든 [파일 이름]을 확인해줘.
초보자가 이해하기 어려운 부분이 있으면 설명해줘.
버그가 있을 것 같은 부분도 알려줘.
고쳐야 할 게 있으면 고쳐줘.
```

**실제 예시:**

```
방금 만든 menu.js를 확인해줘.
초보자가 이해하기 어려운 부분이 있으면 설명해줘.
버그가 있을 것 같은 부분도 알려줘.
고쳐야 할 게 있으면 고쳐줘.
```

### 단계 5: 다음 단계 Prompt

현재 단계가 잘 동작하는 걸 확인했으면, 다음 단계를 시작하는 prompt를 써요. 이 때 **현재 상태를 먼저 설명**하고 다음에 뭘 추가할지 말해요.

```
[다음 단계 prompt 템플릿]

지금 [현재 상태 설명]가 있어.
다음으로 [다음 기능]을 추가하고 싶어.
기존 코드는 최대한 그대로 두고, 필요한 부분만 추가해줘.
```

**실제 예시:**

```
지금 menu.js에 메뉴 10개 담긴 배열이 있어.
다음으로 index.html에 "오늘의 추천 받기" 버튼을 추가하고 싶어.
버튼을 누르면 menu.js에서 랜덤으로 하나를 골라서 버튼 아래에 보여줘.
기존 코드는 최대한 그대로 두고, 필요한 부분만 추가해줘.
```

## 3. 전체 Prompt Set 완성본 예시

실제로 "오늘뭐먹지" 앱을 만드는 전체 흐름이에요. 이 구조를 복사해서 여러분의 서비스에 맞게 바꿔 쓰세요.

```
=== PROMPT SET: 오늘뭐먹지 앱 v1 ===

--- PROMPT 1: 서비스 설명 ---
나는 "오늘뭐먹지" 앱을 만들고 있어.
혼밥하는 직장인이 버튼 하나로 오늘 먹을 메뉴를 랜덤 추천받는 앱이야.
코드는 아직 안 짜도 돼. 내용 이해했다고만 말해줘.

--- PROMPT 2: 기능 분해 ---
메뉴 추천 기능을 가장 작은 단계로 쪼개줘.
각 단계는 30분 안에 끝날 수 있어야 해.
코드는 아직 쓰지 마.

--- PROMPT 3: 첫 구현 ---
menu.js 파일을 새로 만들어줘.
한국 음식 메뉴 10개 담긴 배열 하나만 있으면 돼.

--- PROMPT 4: 검토 ---
방금 만든 menu.js 확인해줘.
초보자가 이해 못 할 부분이나 버그가 있으면 알려줘.

--- PROMPT 5: 다음 단계 ---
지금 menu.js에 메뉴 배열이 있어.
index.html에 추천 버튼 하나 추가해줘.
버튼 누르면 배열에서 랜덤 하나 골라 화면에 보여주면 돼.
기존 코드 건드리지 말고 필요한 것만 추가해줘.
```

## 따라 하기 실습

### 실습 1: 나만의 서비스 설명 Prompt 쓰기

`my-prompts/` 폴더를 만들고 `service-desc.txt` 파일을 생성하세요.

```
my-prompts/
└── service-desc.txt
```

`service-desc.txt`에 아래 템플릿을 복사해서 빈칸을 채우세요.

```
나는 "[서비스 이름]"을 만들고 있어.
이 서비스는 [어떤 사람들이] [무엇을 할 수 있는] 앱이야.
가장 중요한 기능은 [핵심 기능 한 가지]야.
코드는 아직 안 짜도 돼. 내용 이해했다고만 말해줘.
```

**예시 완성본:**

```
나는 "책 읽었어요"를 만들고 있어.
이 서비스는 독서를 좋아하는 사람들이 읽은 책을 기록하고 한 줄 감상을 남길 수 있는 앱이야.
가장 중요한 기능은 책 제목과 감상 한 줄 저장하기야.
코드는 아직 안 짜도 돼. 내용 이해했다고만 말해줘.
```

이 파일을 AI에게 그대로 붙여넣고 반응을 확인하세요.

### 실습 2: 기능 분해 Prompt 쓰고 구현 요청하기

`my-prompts/step-01.txt` 파일을 만드세요.

```
my-prompts/
├── service-desc.txt   ← 실습 1에서 만든 파일
└── step-01.txt        ← 지금 만드는 파일
```

실습 1의 핵심 기능을 아래 형식으로 분해 요청하고, AI의 답을 이 파일에 기록하세요.

```
[분해 요청 - step-01.txt에 기록할 내용]

기능 이름: 책 정보 저장하기

AI에게 보낸 prompt:
"책 정보 저장하기" 기능을 가장 작은 단계로 쪼개줘.
각 단계는 30분 안에 끝날 수 있어야 해.
코드는 아직 쓰지 마.

AI의 답변: (여기에 붙여넣기)
단계 1: ...
단계 2: ...
단계 3: ...

내가 선택한 첫 단계: (위 단계 중 하나 고르기)
```

분해 결과를 바탕으로 단계 1을 구현하는 prompt를 AI에게 보내고, 실제 파일(`books.js` 또는 `index.html`)이 만들어지는 걸 확인하세요.

---

### 실습 3: 검토 → 다음 단계 흐름 완성하기

`my-prompts/step-02.txt` 파일을 만들고, 실습 2에서 만든 파일을 검토 요청한 뒤 다음 단계 prompt까지 이어서 완성하세요.

```
my-prompts/
├── service-desc.txt
├── step-01.txt
└── step-02.txt    ← 검토 결과 + 다음 단계 prompt
```

`step-02.txt` 작성 형식:

```
[검토 요청]
방금 만든 [파일 이름] 확인해줘.
초보자가 이해하기 어려운 부분이나 버그가 있으면 알려줘.

[AI 검토 결과] (붙여넣기)

[다음 단계 prompt]
지금 [현재 완성된 것 설명].
다음으로 [추가할 기능] 해줘.
기존 코드 건드리지 말고 필요한 것만 추가해줘.
```

실습 1, 2, 3을 마치면 여러분만의 서비스를 위한 prompt set 초안이 완성돼요.

## 자주 하는 실수

| 실수 유형 | 상황 | 실제 오류 메시지 또는 증상 | 해결 방법 |
|---|---|---|---|
| 너무 큰 prompt | 한 번에 모든 기능을 요청함 | AI가 엉뚱한 기능을 먼저 만들거나, 일부 기능을 빠뜨림. 명시적 오류는 없음 | 기능 하나만 골라 30분 단위로 쪼개기 |
| 파일 이름 없이 요청 | "버튼 만들어줘" | AI가 새 파일을 만들어야 할지, 기존 파일을 고쳐야 할지 알 수 없어서 임의로 선택함 | prompt에 반드시 파일 이름 포함: `index.html에 버튼 추가해줘` |
| 검토 없이 다음 단계로 이동 | 만든 코드 확인 전에 다음 기능 추가 요청 | `ReferenceError: menuList is not defined` 처럼 이전 단계 실수가 쌓여서 나중에 터짐 | 단계마다 브라우저 또는 터미널에서 직접 실행해서 확인 후 다음으로 |
| "다른 것도 수정해줘"를 붙임 | 구현 요청에 사이드 요청 추가 | 원하지 않는 파일까지 바뀌거나 기존 코드가 사라짐 | 한 prompt에 요청 하나. 추가 요청은 다음 prompt로 분리 |
| 맥락 없이 이어서 요청 | 새 대화창에서 "다음 단계 해줘" | AI가 이전 맥락을 모르므로 처음부터 만들거나 오류 발생: `I don't have context about what was built before` | 새 대화를 시작할 때는 service-desc.txt와 현재 파일 구조를 다시 알려줌 |
| HTML에서 JS 파일 경로 오류 | `<script src="menu.js">` 경로가 틀림 | 브라우저 콘솔: `Failed to load resource: net::ERR_FILE_NOT_FOUND` | 파일이 같은 폴더에 있는지 확인. 다른 폴더면 `src="js/menu.js"` 처럼 경로 수정 |

---

## 확인 체크리스트

- [ ] 내 서비스를 한 문장으로 설명할 수 있다
- [ ] 핵심 기능 하나를 3단계 이하로 쪼갤 수 있다
- [ ] "좋은 prompt"에는 파일 이름과 딱 하나의 요청이 담겨야 한다는 걸 안다
- [ ] 5단계 prompt set 구조(설명 → 분해 → 구현 → 검토 → 다음 단계)를 순서대로 말할 수 있다
- [ ] 실습 1~3을 완료해서 `my-prompts/` 폴더에 파일 3개가 생겼다
- [ ] 각 단계마다 브라우저나 터미널에서 결과를 직접 확인하는 습관을 이해했다
