## 이 장에서 배우는 것

- 데코레이터(decorator)가 무엇인지, 왜 필요한지 이해한다
- `@` 문법을 읽고 직접 작성할 수 있다
- 함수를 인자로 받고 반환하는 패턴을 익힌다
- 실용적인 데코레이터(로깅, 실행 시간 측정, 접근 제한)를 직접 만든다
- `functools.wraps`를 사용해 데코레이터를 올바르게 작성하는 방법을 배운다

---

## 먼저 쉬운 설명

함수를 만들었는데, 여러 함수에 공통으로 넣고 싶은 기능이 생겼다고 생각해 보세요.

예를 들어 "이 함수가 언제 실행됐는지 항상 출력하고 싶다"거나, "이 함수가 얼마나 걸렸는지 알고 싶다"는 경우입니다.

함수마다 일일이 같은 코드를 붙여넣을 수도 있지만, 그러면 코드가 지저분해지고 나중에 고치기도 힘들어집니다.

**데코레이터**는 이 문제를 깔끔하게 해결해 줍니다. 함수에 `@이름` 한 줄만 붙이면, 그 함수가 실행될 때 자동으로 추가 기능이 동작합니다. 마치 케이크 위에 토핑을 얹듯이, 원래 함수를 전혀 건드리지 않고 기능을 덧붙이는 것입니다.

실제 현업에서는 웹 프레임워크(Flask, FastAPI), 테스트 도구(pytest), 클래스 문법(dataclass) 등 거의 모든 곳에서 데코레이터를 씁니다. 이 장을 마치면 그 코드들이 더 이상 낯설지 않을 것입니다.

## 1. 함수도 값이다 — 일급 함수(First-class Function)

데코레이터를 이해하려면 먼저 이것을 알아야 합니다: **파이썬에서 함수는 변수에 담을 수 있고, 다른 함수의 인자로 전달할 수 있습니다.**

```python
# 파일명: first_class.py

def 인사하기():
    print("안녕하세요!")

# 함수를 변수에 담기
내_함수 = 인사하기

# 변수를 통해 함수 호출
내_함수()  # 출력: 안녕하세요!

# 함수를 인자로 받는 함수
def 두_번_실행하기(함수):
    함수()
    함수()

두_번_실행하기(인사하기)
# 출력:
# 안녕하세요!
# 안녕하세요!
```

> **포인트:** `인사하기`와 `인사하기()`는 다릅니다.
> - `인사하기` → 함수 자체(객체)
> - `인사하기()` → 함수를 실행한 결과

## 2. 함수 안에서 함수 만들기 — 중첩 함수(Nested Function)

함수 안에서 새 함수를 정의하고, 그것을 반환할 수도 있습니다.

```python
# 파일명: nested_function.py

def 외부_함수():
    def 내부_함수():
        print("저는 내부 함수입니다.")
    return 내부_함수  # 함수를 반환 (괄호 없음 주의!)

결과 = 외부_함수()
결과()  # 출력: 저는 내부 함수입니다.

# 더 실용적인 예: 인자를 활용한 함수 공장
def 인사_만들기(이름):
    def 인사하기():
        print(f"안녕하세요, {이름}님!")
    return 인사하기

김철수_인사 = 인사_만들기("김철수")
이영희_인사 = 인사_만들기("이영희")

김철수_인사()  # 출력: 안녕하세요, 김철수님!
이영희_인사()  # 출력: 안녕하세요, 이영희님!
```

## 3. 데코레이터의 구조 — @ 없이 먼저 이해하기

데코레이터는 **함수를 인자로 받아서, 새 함수를 반환하는 함수**입니다. 먼저 `@` 없이 직접 써봅니다.

```python
# 파일명: decorator_manual.py

def 로그_데코레이터(원래_함수):
    def 래퍼():
        print(f"[로그] {원래_함수.__name__} 함수 시작")
        원래_함수()  # 원래 함수 실행
        print(f"[로그] {원래_함수.__name__} 함수 종료")
    return 래퍼

def 주문하기():
    print("아메리카노 주문 완료!")

# 수동으로 데코레이터 적용
주문하기 = 로그_데코레이터(주문하기)

주문하기()
# 출력:
# [로그] 주문하기 함수 시작
# 아메리카노 주문 완료!
# [로그] 주문하기 함수 종료
```

위 코드의 `주문하기 = 로그_데코레이터(주문하기)` 한 줄이 바로 `@로그_데코레이터`와 **완전히 같습니다.**

## 4. @ 문법으로 깔끔하게 쓰기

```python
# 파일명: decorator_syntax.py

def 로그_데코레이터(원래_함수):
    def 래퍼():
        print(f"[로그] {원래_함수.__name__} 함수 시작")
        원래_함수()
        print(f"[로그] {원래_함수.__name__} 함수 종료")
    return 래퍼

@로그_데코레이터  # 이 한 줄이 위 섹션의 수동 적용과 같습니다
def 주문하기():
    print("아메리카노 주문 완료!")

@로그_데코레이터
def 결제하기():
    print("카드 결제 완료!")

주문하기()
print("---")
결제하기()
# 출력:

# 아메리카노 주문 완료!
# [로그] 주문하기 함수 종료
# ---
# [로그] 결제하기 함수 시작
# 카드 결제 완료!
# [로그] 결제하기 함수 종료
```

## 5. 인자가 있는 함수에 데코레이터 적용하기

원래 함수가 인자를 받는다면, 래퍼 함수도 그 인자를 받아서 전달해야 합니다. 이때 `*args, **kwargs`를 사용합니다.

```python
# 파일명: decorator_with_args.py

def 로그_데코레이터(원래_함수):
    def 래퍼(*args, **kwargs):  # 어떤 인자든 받을 수 있음
        print(f"[로그] {원래_함수.__name__} 호출됨")
        결과 = 원래_함수(*args, **kwargs)  # 인자를 그대로 전달
        print(f"[로그] {원래_함수.__name__} 반환값: {결과}")
        return 결과  # 원래 함수의 반환값도 그대로 돌려줌
    return 래퍼

@로그_데코레이터
def 합계_계산(a, b):
    return a + b

@로그_데코레이터
def 인사하기(이름, 시간대="낮"):
    return f"{시간대}에 안녕하세요, {이름}님!"

합계_계산(3, 7)
# [로그] 합계_계산 호출됨
# [로그] 합계_계산 반환값: 10

인사하기("박지수", 시간대="저녁")
# [로그] 인사하기 호출됨
# [로그] 인사하기 반환값: 저녁에 안녕하세요, 박지수님!
```

## 6. functools.wraps — 반드시 사용해야 하는 이유

데코레이터를 쓰면 함수 이름과 문서가 래퍼 함수로 덮어씌워지는 문제가 생깁니다. `functools.wraps`로 해결합니다.

```python
# 파일명: functools_wraps.py
import functools

# wraps 없이 작성한 데코레이터 (잘못된 방법)
def 나쁜_데코레이터(원래_함수):
    def 래퍼(*args, **kwargs):
        return 원래_함수(*args, **kwargs)
    return 래퍼

# wraps를 사용한 데코레이터 (올바른 방법)
def 좋은_데코레이터(원래_함수):
    @functools.wraps(원래_함수)  # 이 한 줄이 핵심!
    def 래퍼(*args, **kwargs):
        return 원래_함수(*args, **kwargs)
    return 래퍼

@나쁜_데코레이터
def 함수_A():
    """이 함수는 A입니다."""
    pass

@좋은_데코레이터
def 함수_B():
    """이 함수는 B입니다."""
    pass

print(함수_A.__name__)   # 출력: 래퍼  ← 잘못됨!
print(함수_A.__doc__)    # 출력: None  ← 사라짐!

print(함수_B.__name__)   # 출력: 함수_B  ← 올바름
print(함수_B.__doc__)    # 출력: 이 함수는 B입니다.  ← 유지됨
```

> **규칙:** 데코레이터를 만들 때는 **항상** `@functools.wraps(원래_함수)`를 붙이세요.

## 7. 실용적인 데코레이터 예제

### 7-1. 실행 시간 측정

```python
# 파일명: timer_decorator.py
import functools
import time

def 시간_측정(함수):
    @functools.wraps(함수)
    def 래퍼(*args, **kwargs):
        시작 = time.time()
        결과 = 함수(*args, **kwargs)
        종료 = time.time()
        print(f"[시간] {함수.__name__}: {종료 - 시작:.4f}초")
        return 결과
    return 래퍼

@시간_측정
def 느린_계산(n):
    total = 0
    for i in range(n):
        total += i
    return total

느린_계산(1_000_000)
# 출력 예: [시간] 느린_계산: 0.0521초
```

### 7-2. 로그인 확인 (접근 제한)

```python
# 파일명: auth_decorator.py
import functools

# 현재 로그인한 사용자를 흉내 내는 전역 변수
현재_사용자 = None

def 로그인_필요(함수):
    @functools.wraps(함수)
    def 래퍼(*args, **kwargs):
        if 현재_사용자 is None:
            print("로그인이 필요합니다.")
            return None
        return 함수(*args, **kwargs)
    return 래퍼

@로그인_필요
def 마이페이지_보기():
    print(f"{현재_사용자}님의 마이페이지입니다.")

@로그인_필요
def 주문_내역_보기():
    print(f"{현재_사용자}님의 주문 내역입니다.")

마이페이지_보기()   # 출력: 로그인이 필요합니다.

현재_사용자 = "김개발"
마이페이지_보기()   # 출력: 김개발님의 마이페이지입니다.
주문_내역_보기()    # 출력: 김개발님의 주문 내역입니다.
```

### 7-3. 재시도(Retry) 데코레이터

```python
# 파일명: retry_decorator.py
import functools
import random

def 재시도(최대_횟수=3):
    def 데코레이터(함수):
        @functools.wraps(함수)
        def 래퍼(*args, **kwargs):
            for 시도 in range(1, 최대_횟수 + 1):
                try:
                    return 함수(*args, **kwargs)
                except Exception as e:
                    print(f"[{시도}/{최대_횟수}] 실패: {e}")
                    if 시도 == 최대_횟수:
                        print("최대 재시도 횟수 초과")
                        raise
        return 래퍼
    return 데코레이터

@재시도(최대_횟수=3)
def 불안정한_API_호출():
    if random.random() < 0.7:  # 70% 확률로 실패
        raise ConnectionError("서버 연결 실패")
    print("API 호출 성공!")

불안정한_API_호출()
```

### 실습 1: 함수 호출 횟수 세기

`call_counter.py` 파일을 만들고 다음을 구현하세요.

함수가 몇 번 호출됐는지 자동으로 세는 `호출_카운터` 데코레이터를 작성합니다.

```python
# 파일명: call_counter.py
import functools

def 호출_카운터(함수):
    @functools.wraps(함수)
    def 래퍼(*args, **kwargs):
        래퍼.호출_횟수 += 1
        print(f"[카운터] {함수.__name__} 총 {래퍼.호출_횟수}번 호출됨")
        return 함수(*args, **kwargs)
    래퍼.호출_횟수 = 0  # 함수 객체에 속성 추가
    return 래퍼

@호출_카운터
def 커피_만들기(종류):
    print(f"{종류} 제조 완료!")

커피_만들기("아메리카노")
커피_만들기("라떼")
커피_만들기("카푸치노")
print(f"오늘 총 제조: {커피_만들기.호출_횟수}잔")
# 출력:
# [카운터] 커피_만들기 총 1번 호출됨
# 아메리카노 제조 완료!
# [카운터] 커피_만들기 총 2번 호출됨
# 라떼 제조 완료!
# [카운터] 커피_만들기 총 3번 호출됨
# 카푸치노 제조 완료!
# 오늘 총 제조: 3잔
```

### 실습 3: 캐시(Memoization) 데코레이터 직접 만들기

`my_cache.py` 파일을 만들고 같은 인자로 함수를 다시 호출할 때 계산을 건너뛰는 캐시 데코레이터를 구현하세요. (파이썬 표준 라이브러리의 `functools.lru_cache`와 비슷한 기능입니다.)

```python
# 파일명: my_cache.py
import functools

def 캐시(함수):
    저장소 = {}  # 인자 → 결과를 저장하는 딕셔너리

    @functools.wraps(함수)
    def 래퍼(*args):
        if args in 저장소:
            print(f"[캐시 HIT] {args} → {저장소[args]}")
            return 저장소[args]
        print(f"[계산 중] {args}")
        결과 = 함수(*args)
        저장소[args] = 결과
        return 결과
    return 래퍼

@캐시
def 피보나치(n):
    if n <= 1:
        return n
    return 피보나치(n - 1) + 피보나치(n - 2)

print(피보나치(6))
print("---")
print(피보나치(4))  # 이미 계산됐으므로 캐시에서 바로 반환
```

## 자주 하는 실수

| 실수 | 에러 메시지 / 증상 | 올바른 방법 |
|------|-------------------|-------------|
| 래퍼 함수에서 원래 함수의 반환값을 `return`하지 않음 | 함수 호출 결과가 항상 `None` | `래퍼` 안에서 `return 원래_함수(...)` 로 반환값을 전달 |
| 데코레이터 적용 시 함수를 호출해 버림 (`@함수()`) | `TypeError: 'NoneType' object is not callable` 또는 즉시 실행됨 | `@함수` 처럼 괄호 없이 작성 |
| `functools.wraps` 미사용 | `__name__`이 `래퍼`, `__doc__`이 `None` | 래퍼 함수 위에 `@functools.wraps(원래_함수)` 추가 |
| 인자 있는 함수에 `*args, **kwargs` 미사용 | `TypeError: 래퍼() takes 0 positional arguments but 1 was given` | `def 래퍼(*args, **kwargs)` 로 선언하고 `원래_함수(*args, **kwargs)` 전달 |
| 중첩 데코레이터에서 `래퍼`를 `return`하지 않음 | `TypeError: 'NoneType' object is not callable` | 외부 함수(데코레이터) 마지막에 `return 래퍼` 작성 |
| 인자를 받는 데코레이터에서 레벨을 하나 빠뜨림 | `TypeError: 함수() takes 1 positional argument but 2 were given` | `데코레이터 팩토리 → 데코레이터 → 래퍼` 의 3단 구조 확인 |

---

## 확인 체크리스트

- [ ] 파이썬에서 함수가 일급 객체(first-class object)라는 것이 무엇인지 설명할 수 있다
- [ ] `@데코레이터`가 `함수 = 데코레이터(함수)`와 동일하다는 것을 이해한다
- [ ] `*args, **kwargs`를 사용해 인자를 그대로 전달하는 이유를 말할 수 있다
- [ ] `functools.wraps`가 없으면 어떤 문제가 생기는지 알고 있다
- [ ] 데코레이터 안에서 원래 함수의 반환값을 `return`해야 한다는 것을 기억한다
- [ ] `@A` `@B` 처럼 여러 데코레이터를 겹쳐 쓸 때 적용 순서를 설명할 수 있다
- [ ] 실습 1~3을 오류 없이 직접 실행해 봤다
