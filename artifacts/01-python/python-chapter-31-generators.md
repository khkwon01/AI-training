## 이 장에서 배우는 것

- 이터레이터(iterator)가 무엇인지, 파이썬이 내부적으로 어떻게 사용하는지 이해한다
- `__iter__`와 `__next__` 메서드를 직접 구현해 커스텀 이터레이터를 만든다
- `yield` 키워드로 제너레이터 함수를 작성한다
- 제너레이터 표현식(generator expression)을 리스트 컴프리헨션과 비교해 사용한다
- 메모리 효율이 중요한 상황에서 제너레이터를 선택하는 근거를 설명한다

## 먼저 쉬운 설명

책 한 권을 통째로 외운 다음 질문에 답하는 사람을 상상해 보세요. 그 사람은 답하기 전에 책 전체를 머릿속에 올려놓아야 합니다. 반면 책을 펼쳐 가며 필요한 페이지만 읽는 사람은 책 전체를 기억할 필요가 없습니다.

파이썬의 **이터레이터**와 **제너레이터**가 바로 두 번째 방식입니다.

```python
# 이 코드는 100만 개의 숫자를 한 번에 메모리에 올립니다
numbers = list(range(1_000_000))   # 약 8MB

# 이 코드는 숫자를 한 번에 하나씩만 만듭니다
numbers = range(1_000_000)         # 거의 0MB
```

데이터 파일을 줄 단위로 읽거나, 무한한 수열을 처리하거나, 처리 파이프라인을 연결할 때 제너레이터는 코드를 간결하고 빠르게 만들어 줍니다. 이 장을 마치면 파이썬 `for` 루프가 내부적으로 어떻게 동작하는지도 완전히 이해하게 됩니다.

## 1. 이터러블과 이터레이터의 차이

**이터러블(iterable)** 은 반복할 수 *있는* 객체입니다. 리스트, 문자열, 딕셔너리가 모두 해당합니다.  
**이터레이터(iterator)** 는 실제로 값을 하나씩 꺼내는 객체입니다. `iter()`를 호출하면 이터러블에서 이터레이터를 얻습니다.

```python
# 파일명: 01_iterator_basics.py

과일들 = ["사과", "바나나", "체리"]

# iter()로 이터레이터 생성
이터레이터 = iter(과일들)

print(next(이터레이터))   # 사과
print(next(이터레이터))   # 바나나
print(next(이터레이터))   # 체리
print(next(이터레이터))   # StopIteration 예외 발생!
```

`for` 루프는 내부에서 이 과정을 자동으로 처리합니다.

```python
# for 루프가 실제로 하는 일
이터레이터 = iter(과일들)
while True:
    try:
        값 = next(이터레이터)
        print(값)
    except StopIteration:
        break
```

> **핵심 규칙**: 이터레이터는 반드시 `__iter__`와 `__next__` 두 메서드를 가집니다.

## 2. 커스텀 이터레이터 클래스 만들기

직접 이터레이터 클래스를 만들면 `for` 루프에서 동작하는 나만의 객체를 설계할 수 있습니다.

```python
# 파일명: 02_custom_iterator.py

class 카운트다운:
    """숫자를 역순으로 세는 이터레이터"""

    def __init__(self, 시작):
        self.현재 = 시작

    def __iter__(self):
        # 이터레이터 자기 자신을 반환
        return self

    def __next__(self):
        if self.현재 <= 0:
            raise StopIteration   # 반복 종료 신호
        값 = self.현재
        self.현재 -= 1
        return 값


# 사용
for 숫자 in 카운트다운(5):
    print(숫자, end=" ")
# 출력: 5 4 3 2 1

# list()로 한 번에 수집하기
결과 = list(카운트다운(3))
print(결과)   # [3, 2, 1]
```

이터레이터를 한 번 소진하면 다시 처음부터 반복할 수 없습니다. 새 인스턴스를 만들어야 합니다.

```python
cd = 카운트다운(3)
print(list(cd))   # [3, 2, 1]
print(list(cd))   # []  ← 이미 소진됨
```

## 3. yield로 제너레이터 함수 작성하기

`yield` 키워드가 있으면 그 함수는 **제너레이터 함수**가 됩니다. 호출하면 제너레이터 객체(=이터레이터)를 반환합니다. `__iter__`와 `__next__`를 직접 구현하지 않아도 됩니다.

```python
# 파일명: 03_generator_function.py

def 카운트다운(시작):
    while 시작 > 0:
        yield 시작   # 여기서 멈추고 값을 돌려줌
        시작 -= 1    # next() 호출 시 여기서 재개


gen = 카운트다운(5)
print(type(gen))        # <class 'generator'>
print(next(gen))        # 5
print(next(gen))        # 4

for 숫자 in 카운트다운(3):
    print(숫자, end=" ")
# 출력: 3 2 1
```

`yield`는 함수를 **일시 정지**시킵니다. 다음 `next()` 호출 때 정확히 그 지점에서 다시 실행됩니다. 지역 변수와 실행 흐름이 모두 유지됩니다.

```python
def 단계별_로그():
    print("1단계 시작")
    yield "1단계 완료"
    print("2단계 시작")
    yield "2단계 완료"
    print("3단계 시작")
    yield "3단계 완료"


for 단계 in 단계별_로그():
    print(f"받은 값: {단계}")

# 출력:
# 1단계 시작
# 받은 값: 1단계 완료
# 2단계 시작
# 받은 값: 2단계 완료
# 3단계 시작
# 받은 값: 3단계 완료
```

## 4. 실용 예제 — 대용량 파일 줄 단위 처리

제너레이터가 가장 빛나는 순간은 파일을 줄 단위로 처리할 때입니다.

```python
# 파일명: 04_file_generator.py

def csv_행_읽기(파일경로, 건너뛸_헤더=True):
    """CSV 파일을 한 줄씩 yield합니다."""
    with open(파일경로, encoding="utf-8") as f:
        if 건너뛸_헤더:
            next(f)   # 헤더 행 건너뜀
        for 줄 in f:
            yield 줄.strip().split(",")


def 금액_합계(파일경로, 금액_열_인덱스=2):
    합계 = 0
    for 행 in csv_행_읽기(파일경로):
        try:
            합계 += float(행[금액_열_인덱스])
        except (ValueError, IndexError):
            continue
    return 합계


# 사용 예 (파일이 수백만 행이어도 메모리 문제 없음)
# total = 금액_합계("sales_2024.csv")
# print(f"총 매출: {total:,.0f}원")
```

같은 작업을 리스트로 처리한다면 파일 전체를 메모리에 올려야 합니다.

```python
# 메모리를 많이 쓰는 방식
모든_행 = open("sales_2024.csv").readlines()   # 파일 전체를 RAM에 로드
```

## 5. 제너레이터 표현식

리스트 컴프리헨션과 문법이 거의 같지만 **대괄호 대신 소괄호**를 씁니다. 결과를 즉시 만들지 않고 필요할 때 하나씩 계산합니다.

```python
# 파일명: 05_generator_expression.py

# 리스트 컴프리헨션 — 즉시 모든 값 생성
제곱_리스트 = [x**2 for x in range(10)]
print(제곱_리스트)          # [0, 1, 4, 9, 16, 25, 36, 49, 64, 81]
print(type(제곱_리스트))    # <class 'list'>

# 제너레이터 표현식 — 아직 값이 없음
제곱_제너레이터 = (x**2 for x in range(10))
print(제곱_제너레이터)      # <generator object <genexpr> at 0x...>
print(type(제곱_제너레이터))  # <class 'generator'>

# 필요할 때 하나씩 소비
print(next(제곱_제너레이터))   # 0
print(next(제곱_제너레이터))   # 1

# sum(), max(), min()에 바로 넣을 수 있음
총합 = sum(x**2 for x in range(1, 101))
print(f"1부터 100까지 제곱합: {총합}")   # 338350
```

| 구분 | 리스트 컴프리헨션 | 제너레이터 표현식 |
|---|---|---|
| 문법 | `[식 for ...]` | `(식 for ...)` |
| 메모리 | 전체 저장 | 하나씩 생성 |
| 재사용 | 가능 | 한 번만 소비 |
| 속도 | 미리 계산 | 필요 시 계산 |

## 6. yield from — 제너레이터 합성하기

다른 이터러블의 값을 통째로 위임할 때 `yield from`을 씁니다. 중첩 루프보다 코드가 훨씬 깔끔해집니다.

```python
# 파일명: 06_yield_from.py

def 1분기():
    yield "1월"
    yield "2월"
    yield "3월"

def 2분기():
    yield "4월"
    yield "5월"
    yield "6월"

def 상반기():
    yield from 1분기()
    yield from 2분기()

for 월 in 상반기():
    print(월, end=" ")
# 출력: 1월 2월 3월 4월 5월 6월


# 중첩 리스트 펼치기
def 평탄화(중첩리스트):
    for 항목 in 중첩리스트:
        if isinstance(항목, list):
            yield from 평탄화(항목)   # 재귀적으로 위임
        else:
            yield 항목

data = [1, [2, 3], [4, [5, 6]]]
print(list(평탄화(data)))   # [1, 2, 3, 4, 5, 6]
```

```python
# 파일명: log_analyzer.py

def 줄_읽기(파일경로):
    with open(파일경로, encoding="utf-8") as f:
        yield from f

def 에러만_필터(줄들):
```

## 자주 하는 실수

| 실수 | 에러 메시지 또는 증상 | 원인 | 수정 방법 |
|---|---|---|---|
| 소진된 제너레이터 재사용 | 두 번째 `list()` 가 `[]` 반환 | 제너레이터는 한 번만 소비 가능 | 함수를 다시 호출해 새 제너레이터 생성 |
| `next()` 를 다 쓴 후 호출 | `StopIteration` | 값이 더 없음 | `next(gen, 기본값)` 형식으로 기본값 지정 |
| 제너레이터 함수에 `return 값` | `SyntaxError` (Python 2) / 제너레이터 조기 종료 | `return` 은 `StopIteration` 을 일으킴 | 값 반환은 `yield` 사용 |
| 무한 제너레이터를 `list()` 로 변환 | 프로그램 멈춤 / 메모리 부족 | 끝이 없는 수열 | `itertools.islice()` 로 개수 제한 |
| `__iter__` 가 `self` 가 아닌 새 객체 반환 | `for` 루프에서 예상치 못한 동작 | 이터레이터는 `self` 를 반환해야 함 | `return self` 로 수정 |
| 제너레이터 표현식 괄호 혼동 | `TypeError: 'generator' object is not subscriptable` | `gen[0]` 처럼 인덱스 접근 불가 | `list(gen)[0]` 또는 `next(gen)` 사용 |

---

## 확인 체크리스트

- [ ] `iter()`와 `next()`를 직접 호출해 `for` 루프의 동작을 재현할 수 있다
- [ ] `__iter__`와 `__next__`를 구현해 클래스를 이터레이터로 만들 수 있다
- [ ] `yield` 키워드로 제너레이터 함수를 작성하고, `yield` 가 일시 정지 지점임을 설명할 수 있다
- [ ] 제너레이터 표현식과 리스트 컴프리헨션의 차이를 메모리 관점에서 설명할 수 있다
- [ ] `yield from` 으로 두 제너레이터를 합성할 수 있다
- [ ] `itertools.islice()`로 무한 제너레이터에서 원하는 개수만 꺼낼 수 있다
- [ ] 소진된 제너레이터를 새로 만드는 방법을 알고 있다
- [ ] 실습 3의 파이프라인 패턴을 새 문제에 응용할 수 있다
