## 왜 실행 방법을 구분해서 배워야 하나?

처음 Python을 배울 때 가장 흔한 패턴이 있다. 코드가 실행이 안 되거나 결과가 이상한데, 왜 그런지 모르겠어서 `print()`를 여기저기 추가하다가 코드가 지저분해진다.

또는 반대로 디버거가 있다는 걸 알지만 어떻게 쓰는지 몰라서 항상 `print()`에만 의존한다.

세 가지 실행 방법을 제대로 알면:
- 터미널로 실행해야 할 때와 버튼으로 실행해도 되는 때를 구분할 수 있다
- 코드가 이상할 때 `print()`를 10개 추가하는 대신 디버거로 30초 안에 원인을 찾을 수 있다
- 팀 프로젝트나 실제 개발 환경에서 혼란 없이 작업할 수 있다

## 1. 방법 1: 터미널 실행

```bash
python3 hello.py
```

가장 기본적인 방법이다. 터미널(Terminal 또는 PowerShell)에서 명령어를 직접 입력해서 실행한다.

### 장점

**어떤 Python으로 실행되는지 명확하게 보인다**

터미널에서 먼저 Python 버전을 확인할 수 있다.

```bash
python3 --version
# Python 3.11.4
```

이 버전의 Python으로 실행된다는 것이 명확하다.

**오류 메시지 전체가 그대로 출력된다**

```bash
python3 my_script.py
```

```
Traceback (most recent call last):
  File "my_script.py", line 8, in <module>
    result = calculate(x, y)
  File "my_script.py", line 3, in calculate
    return a / b
ZeroDivisionError: division by zero
```

어느 파일의 몇 번째 줄에서 오류가 났는지, 어떤 함수를 타고 들어갔는지 전부 보인다.

**명령줄 인수를 직접 전달할 수 있다**

```bash
python3 calculator.py 10 20
python3 calculator.py --mode add 15 30
```

`sys.argv`를 사용하는 프로그램은 터미널에서만 제대로 테스트할 수 있다.

**파일 경로 문제가 생기지 않는다**

```bash
pwd              # 현재 위치 확인
# /Users/username/python-study

python3 hello.py  # 현재 폴더의 hello.py 실행
```

터미널은 현재 위치를 직접 볼 수 있으므로 "어느 파일이 실행됐지?" 하는 혼란이 없다.

### 주의할 점: 터미널 위치 확인

터미널이 파일이 있는 폴더에 있어야 한다.

```bash
pwd              # 현재 위치 확인
ls               # 현재 폴더의 파일 목록 확인

cd python-study  # 올바른 폴더로 이동
python3 hello.py
```

파일이 없는 폴더에서 실행하면:
```
python3: can't open file 'hello.py': [Errno 2] No such file or directory
```

이 오류가 나면 파일이 없는 게 아니라 **터미널 위치가 잘못된 것**이다.

### 언제 쓰면 좋은가

- 처음 Python을 배울 때 (기본으로 쓸 것)
- `input()` 함수를 사용하는 프로그램
- 명령줄 인수를 받는 프로그램
- 어떤 Python 버전, 어떤 가상환경으로 실행되는지 확실히 해야 할 때
- 오류 메시지 전체를 보고 싶을 때

**처음 배울 때는 이 방법을 기본으로 쓰는 것이 좋다.** 무슨 일이 일어나는지 가장 투명하게 볼 수 있다.

## 2. 방법 2: VS Code 실행 버튼 (▶)

VS Code 오른쪽 위의 삼각형(▶) 버튼을 클릭하면 현재 열린 파일이 실행된다.

### 장점

- 마우스 클릭 한 번으로 빠르게 실행할 수 있다
- 결과가 VS Code 하단 터미널에 바로 나타난다
- 파일 저장 후 바로 확인하는 흐름이 자연스럽다

### 주의할 점 1: 인터프리터 설정 확인

실행 버튼은 VS Code에 설정된 Python 인터프리터를 사용한다. 인터프리터가 잘못 설정되어 있으면 설치한 패키지를 못 찾거나 다른 Python 버전이 실행된다.

**현재 인터프리터 확인 방법:**

VS Code 하단 상태 표시줄을 보면:
```
Python 3.11.4 ('.venv': venv)   ← 가상환경 Python (올바름)
Python 3.11.4 64-bit             ← 전역 Python (가상환경 패키지 못 찾을 수 있음)
```

인터프리터를 바꾸려면:
1. 상태 표시줄의 Python 버전 클릭
2. 팝업에서 원하는 인터프리터 선택
3. 또는 `Cmd/Ctrl + Shift + P` → "Python: Select Interpreter"

### 주의할 점 2: 저장이 안 된 코드는 이전 버전이 실행됨

```
수정한 코드를 저장하지 않고 ▶ 버튼을 누르면 이전에 저장된 코드가 실행된다.
```

실행 전 반드시 저장:
```
Cmd + S (Mac)
Ctrl + S (Windows/Linux)
```

파일 탭에 작은 점(●)이 표시되어 있으면 저장이 안 된 상태다.

### 주의할 점 3: input() 함수와의 충돌

`input()` 함수를 쓰는 코드는 실행 버튼보다 터미널 실행이 더 안정적이다.

```python
name = input("이름을 입력하세요: ")
print(f"안녕하세요, {name}!")
```

▶ 버튼으로 실행하면 입력 창과 출력 창이 뒤섞여서 혼란스러울 수 있다. 이런 코드는 터미널에서 직접 실행하는 것이 좋다.

### 언제 쓰면 좋은가

- `input()` 함수가 없는 간단한 스크립트 확인
- 코드를 빠르게 테스트하고 싶을 때
- 이미 인터프리터 설정이 올바른지 확인된 상태
- 터미널 창을 별도로 열기 귀찮을 때

## 3. 방법 3: VS Code 디버거 (F5)

디버거는 코드가 **어디서, 어떻게, 어떤 값으로** 실행되는지 단계별로 확인할 수 있는 도구다.

### 3-1. 중단점(Breakpoint) 설정하기

줄 번호 왼쪽 영역을 클릭하면 빨간 점(●)이 생긴다. 이것이 중단점이다.

```python
def calculate(a, b):
    result = a + b    # ← 이 줄 번호 왼쪽을 클릭 → 빨간 점 생김
    return result

x = calculate(3, 5)
print(x)
```

코드 실행 중 중단점이 있는 줄에 도달하면 **실행이 그 자리에서 멈춘다.** 멈춘 상태에서 변수 값을 확인하고, 한 줄씩 실행하며 코드 흐름을 추적할 수 있다.

**중단점 관리:**
- 설정: 줄 번호 왼쪽 클릭
- 제거: 빨간 점을 다시 클릭
- 일시 비활성화: 빨간 점 위에서 오른쪽 클릭 → "Disable Breakpoint"
- 전체 제거: `Shift+Cmd+F9` (Mac) 또는 왼쪽 패널 BREAKPOINTS에서 관리

### 3-2. 디버그 실행하기

`F5` 키를 누르면 디버그 모드로 실행된다.

처음 실행하면 디버그 구성을 물어볼 수 있다. "Python File"을 선택하면 현재 파일이 디버그 모드로 실행된다.

중단점에서 멈추면 VS Code가 다음을 보여준다:

**1) 현재 실행 줄 강조 (노란 화살표)**
```python
def calculate(a, b):
→   result = a + b    # ← 노란 화살표가 여기에 있음 (아직 실행 전)
    return result
```

**2) VARIABLES 패널 (왼쪽 패널)**
```
VARIABLES
  Locals
    a = 3
    b = 5
  Globals
    calculate = <function calculate at 0x...>
```

함수 안에 있으면 그 함수의 매개변수와 지역 변수가 자동으로 표시된다.

**3) CALL STACK 패널**
```
CALL STACK
  calculate (debug_test.py:2)
  <module> (debug_test.py:6)
```

어떤 함수가 어떤 순서로 호출됐는지 보여준다.

### 3-3. 디버그 컨트롤 (단계 실행)

중단점에서 멈춘 후 어떻게 진행할지 선택할 수 있다.

| 버튼 | 단축키 | 의미 | 언제 쓰는가 |
|------|--------|------|------------|
| Continue | F5 | 다음 중단점까지 계속 실행 | 이미 이 줄은 괜찮고 다음 중단점으로 바로 가고 싶을 때 |
| Step Over | F10 | 현재 줄 실행하고 다음 줄로 | 함수 안에 들어가지 않고 이 줄만 실행할 때 |
| Step Into | F11 | 함수 안으로 들어가기 | 함수 내부가 어떻게 돌아가는지 보고 싶을 때 |
| Step Out | Shift+F11 | 현재 함수에서 나오기 | 함수 안에서 나머지 부분은 건너뛰고 싶을 때 |
| Restart | Shift+Cmd+F5 | 디버그 처음부터 다시 | 다시 처음부터 실행하고 싶을 때 |
| Stop | Shift+F5 | 디버그 종료 | 디버그를 끝낼 때 |

### 3-4. 변수 값 직접 확인하기 (Watch)

WATCH 패널에 변수 이름이나 표현식을 추가하면 실행 중에 값을 계속 모니터링할 수 있다.

```
WATCH 패널에 추가 → + 버튼 클릭
→ result 입력
→ result * 2 입력 (표현식도 가능)
```

단계 실행을 할 때마다 추가한 변수/표현식의 값이 자동으로 업데이트된다.

### 3-5. 언제 쓰면 좋은가

- 변수 값이 예상과 다를 때 (왜 이 값이 나왔지?)
- 반복문이나 조건문이 예상대로 실행되는지 확인할 때
- 함수 호출 흐름을 단계별로 추적할 때
- `print()`를 여러 곳에 추가하는 것보다 빠르게 확인하고 싶을 때
- 오류가 어느 줄에서 생기는지 정확히 찾고 싶을 때

## 4. 세 가지 방법 비교

| 항목 | 터미널 실행 | 실행 버튼 ▶ | 디버거 F5 |
|------|-----------|------------|----------|
| 실행 속도 | 빠름 | 빠름 | 약간 느림 |
| 편의성 | 명령어 입력 필요 | 클릭 한 번 | 설정 필요 |
| 투명성 | 높음 (어떤 Python인지 명확) | 보통 | 높음 |
| 변수 값 확인 | print() 필요 | print() 필요 | 자동 표시 |
| 오류 메시지 | 전체 출력 | 전체 출력 | 전체 출력 + 줄 강조 |
| 명령줄 인수 | 가능 | 불편 | launch.json 설정 필요 |
| input() 처리 | 안정적 | 가끔 불편 | 안정적 |
| 버그 추적 | print() 추가해야 함 | print() 추가해야 함 | 단계 실행으로 즉시 |
| 추천 상황 | 기본, input() 사용 시 | 빠른 확인 | 버그 추적, 로직 이해 |

### 상황별 추천 방법

**처음 Python을 배울 때:** 터미널 실행을 기본으로 한다.

**간단한 코드 빠르게 확인할 때:** 저장 후 ▶ 버튼 클릭.

**코드가 이상한데 원인을 모를 때:** 디버거로 중단점 설정 후 단계 실행.

**input()이 있는 프로그램:** 터미널 실행.

**오류 없이 실행되는데 결과가 틀릴 때:** 디버거로 중간값 확인.

## 5. 자주 막히는 지점

### "F5를 눌렀는데 launch.json이 필요하다고 나와요"

처음 디버그 실행 시 디버그 구성을 선택하는 팝업이 뜬다.

```
Select a debug configuration:
  Python File    ← 이것 선택
  Django
  Flask
  ...
```

"Python File"을 선택하면 현재 열린 파일이 디버그 모드로 실행된다.

### "중단점을 설정했는데 멈추지 않아요"

중단점이 실제로 실행되는 코드 줄에 있는지 확인한다. 함수 정의 줄(`def`)은 정의만 하는 줄이라 멈추지 않는다.

```python
def calculate(a, b):   # ← 여기에 중단점: 실행 시 멈추지 않음
    result = a + b     # ← 여기에 중단점: 함수가 실제 호출될 때 멈춤
    return result
```

### "VARIABLES 패널에 변수가 안 보여요"

두 가지 경우:
1. 중단점이 아직 해당 변수가 만들어지기 전 줄에 있다 → 변수가 만들어지는 줄 이후에 중단점 설정
2. 전역 변수는 "Globals" 항목을 펼쳐야 보인다

### "▶ 버튼인데 수정한 코드가 안 반영돼요"

파일 탭에 점(●)이 있으면 저장이 안 된 상태다. `Cmd/Ctrl+S`로 저장 후 다시 실행한다.

### "터미널에서 `python3`가 명령을 못 찾는다고 나와요"

```bash
python3: command not found
```

Python이 설치되지 않았거나, 경로 설정이 안 된 것이다. `python` (숫자 없이) 으로 시도해보고, 안 되면 Python 설치를 확인한다.

## 실습

### 실습 1: 터미널 실행 연습 (따라 하기)

`debug_test.py` 파일을 만들고 아래 코드를 입력한다.

```python
def add(a, b):
    result = a + b
    return result

def multiply(a, b):
    result = a * b
    return result

x = add(3, 5)
y = multiply(x, 2)
print(f"add(3, 5) = {x}")
print(f"multiply({x}, 2) = {y}")
print(f"최종 결과: {y}")
```

터미널에서 파일이 있는 폴더로 이동한 후 실행한다.

```bash
pwd          # 현재 위치 확인
ls           # debug_test.py가 보이는지 확인
python3 debug_test.py
```

예상 출력:
```
add(3, 5) = 8
multiply(8, 2) = 16
최종 결과: 16
```

**직접 해보기:** 터미널 위치를 다른 폴더로 이동(`cd ..`)한 후 같은 명령을 실행해보자. 어떤 오류가 나는지 확인하고, 다시 올바른 폴더로 돌아가서 실행해보자.

### 실습 2: 실행 버튼(▶) 연습 (따라 하기)

위에서 만든 `debug_test.py` 파일을 VS Code에서 열고:

1. 코드 일부를 수정한다. 예를 들어 `add(3, 5)` → `add(10, 20)`으로 바꾼다.
2. **저장하지 않고** ▶ 버튼을 눌러본다. 어떤 결과가 나오는지 확인한다.
3. `Cmd/Ctrl+S`로 저장 후 다시 ▶ 버튼을 눌러본다. 결과가 달라지는지 확인한다.
4. VS Code 하단 상태 표시줄에서 현재 인터프리터를 확인한다.

아래처럼 `input()`이 있는 코드도 만들어서 ▶ 버튼과 터미널 실행의 차이를 비교해보자.

```python
# input_test.py
name = input("이름을 입력하세요: ")
age = input("나이를 입력하세요: ")
```

### 실습 3: 디버거로 중간값 확인하기 (따라 하기)

아래 코드에 버그가 있다. 디버거를 사용해서 어디서 문제가 생기는지 찾는다.

`buggy.py` 파일을 만들고:

```python
def sum_list(numbers):
    total = 0
    for n in numbers:
        total = n   # 버그: += 가 아니라 = 사용
    return total

def average_list(numbers):
    total = sum_list(numbers)
    count = len(numbers)
    return total / count

data = [10, 20, 30, 40, 50]
result = average_list(data)
print(f"평균: {result}")   # 예상: 30.0
```

**디버거 사용 순서:**

1. `total = n` 줄 번호 왼쪽을 클릭해서 중단점(빨간 점)을 설정한다.

2. `F5`를 눌러 디버그 모드로 실행한다.

3. 첫 번째로 중단점에서 멈추면 VARIABLES 패널을 확인한다.
   ```
   VARIABLES
     Locals
       n = 10
       numbers = [10, 20, 30, 40, 50]
       total = 0
   ```

4. `F10`을 눌러 한 줄 실행한다. `total` 값이 어떻게 바뀌는지 확인한다.
   ```
   total = 10   (n 값이 total에 그대로 저장됨)
   ```

5. 다시 `F10`을 눌러 반복문이 다음 순서로 넘어갈 때 확인한다.
   ```
   n = 20
   total = 10   (아직 이 줄 실행 전)
   ```
   `F10`을 다시 누르면:
   ```
   total = 20   (누적되지 않고 덮어써짐!)
   ```

6. 버그 발견: `total = n`이 누산이 아니라 덮어쓰기를 하고 있다. `total += n`으로 수정한다.

**직접 해보기:** 버그를 수정한 후 다시 디버거로 실행해서 `total` 값이 올바르게 누산되는지 확인해보자.

```python
# 수정 후
def sum_list(numbers):
    total = 0
    for n in numbers:
        total += n   # 수정됨
    return total
```

예상 출력 (수정 후):
```
평균: 30.0
```

**추가 실습:** `average_list` 함수에도 중단점을 추가하고, `sum_list`가 돌려준 값이 `total`에 올바르게 들어오는지 F11 (Step Into)로 확인해보자.

## 자주 하는 실수 정리표

| 상황 | 증상 | 해결 방법 |
|------|------|----------|
| ▶ 버튼인데 이전 코드가 실행됨 | 저장 안 된 코드 실행 | `Cmd/Ctrl+S` 저장 후 실행 |
| 디버그 중 변수가 안 보임 | VARIABLES 패널 비어있음 | 중단점이 변수 생성 이후 줄에 있는지 확인 |
| F5 눌렀는데 구성 선택 팝업 | 처음 디버그 실행 | "Python File" 선택 |
| ▶ 버튼이 다른 파일 실행 | 포커스가 다른 파일에 있음 | 실행할 파일 탭 클릭 후 ▶ |
| 터미널에서 파일을 못 찾음 | `No such file or directory` | `ls`로 파일 확인 후 올바른 폴더로 `cd` |
| 중단점에서 안 멈춤 | 실행되지 않는 코드에 중단점 | 실제로 호출되는 줄에 중단점 설정 |
| F10과 F11 차이를 모름 | 원하지 않는 깊이로 들어감 | F10: 함수 건너뜀, F11: 함수 안으로 |
