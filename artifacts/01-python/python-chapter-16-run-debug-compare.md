# Chapter 16: 터미널 실행 vs 실행 버튼 vs 디버그

## 이 장에서 배우는 것

- Python 코드를 실행하는 3가지 방법과 차이
- 터미널 실행이 왜 기본으로 좋은지
- VS Code 실행 버튼(▶)을 쓸 때 주의할 점
- 디버그 모드에서 중단점(breakpoint)으로 코드를 단계별로 확인하는 방법
- 어떤 상황에서 어떤 방법을 쓸지 판단하기

---

## 먼저 쉬운 설명

Python 코드를 실행하는 방법은 하나가 아니다.

- 터미널에서 `python3 파일.py` 입력
- VS Code 오른쪽 위 ▶ 버튼 클릭
- `F5` 키로 디버그 모드 실행

세 가지 모두 같은 코드를 실행하지만, 용도와 장단점이 다르다. 언제 어느 방법을 쓰면 좋은지 알면 더 효율적으로 작업할 수 있다.

---

## 1. 방법 1: 터미널 실행

```bash
python3 hello.py
```

### 장점

- 어떤 Python으로 실행되는지 명확히 보인다
- 오류 메시지 전체가 그대로 출력된다
- 터미널 위치가 코드 경로와 연결되어 파일을 직접 이해할 수 있다
- 명령줄 인수(`sys.argv`)를 직접 전달할 수 있다

```bash
python3 calculator.py 10 20
```

### 주의할 점

- 터미널이 파일이 있는 폴더에 있어야 한다

```bash
pwd              # 현재 위치 확인
cd python-study  # 올바른 폴더로 이동
python3 hello.py
```

**처음 배울 때는 이 방법을 기본으로 쓰는 것이 좋다.** 무슨 일이 일어나는지 가장 투명하게 볼 수 있다.

---

## 2. 방법 2: VS Code 실행 버튼 (▶)

오른쪽 위 삼각형(▶) 버튼을 클릭하면 현재 열린 파일이 실행된다.

### 장점

- 빠르고 편하다
- 결과가 VS Code 하단 터미널에 바로 나타난다

### 주의할 점

**인터프리터가 올바르게 설정되어 있어야 한다.**

실행 버튼은 VS Code에 설정된 Python 인터프리터를 사용한다. 인터프리터가 잘못 설정되어 있으면 설치한 패키지를 못 찾거나 다른 Python 버전이 실행된다.

상태 표시줄에서 현재 인터프리터 확인:
```
Python 3.11.4 ('.venv': venv)   ← 가상환경 Python
Python 3.11.4 64-bit             ← 전역 Python
```

**출력 위치가 INPUT 창과 TERMINAL 창이 섞일 수 있다.**

`input()` 함수를 쓰는 코드는 실행 버튼보다 터미널 실행이 더 안정적이다.

---

## 3. 방법 3: 디버그 모드 (F5)

코드가 어디서 어떻게 실행되는지 단계별로 확인할 수 있다.

### 중단점(Breakpoint) 설정

줄 번호 왼쪽을 클릭하면 빨간 점(●)이 생긴다. 코드가 그 줄에 도달하면 실행이 멈춘다.

```python
def calculate(a, b):
    result = a + b    # ← 여기에 중단점 설정
    return result

x = calculate(3, 5)
print(x)
```

### 디버그 실행

`F5` 키를 누르면 디버그 모드로 실행된다.

중단점에서 멈추면 왼쪽 패널에 **현재 변수 값**이 표시된다:
```
VARIABLES
  a = 3
  b = 5
  result = 8   ← 아직 return 전
```

### 디버그 컨트롤

| 버튼 | 단축키 | 의미 |
|------|--------|------|
| Continue | F5 | 다음 중단점까지 계속 실행 |
| Step Over | F10 | 현재 줄 실행하고 다음 줄로 |
| Step Into | F11 | 함수 안으로 들어가기 |
| Step Out | Shift+F11 | 현재 함수에서 나오기 |
| Stop | Shift+F5 | 디버그 종료 |

### 언제 쓰면 좋은가

- 변수 값이 예상과 다를 때
- 반복문이나 조건문이 예상대로 실행되는지 확인할 때
- 함수 호출 흐름을 단계별로 추적할 때
- `print()` 를 여러 곳에 추가하는 것보다 빠르게 확인할 때

## 4. 세 가지 방법 비교

| 항목 | 터미널 실행 | 실행 버튼 ▶ | 디버그 F5 |
|------|-----------|------------|----------|
| 속도 | 보통 | 빠름 | 보통 |
| 투명성 | 높음 | 보통 | 높음 |
| 변수 확인 | print() 필요 | print() 필요 | 자동 표시 |
| 명령줄 인수 | 가능 | 불편 | launch.json 설정 필요 |
| input() 처리 | 안정적 | 가끔 불편 | 안정적 |
| 추천 상황 | 기본, 처음 배울 때 | 빠른 확인 | 버그 추적 |

## 5. 따라 하기 실습

### 실습 1. 세 가지 방법으로 같은 코드 실행하기

`debug_test.py` 파일을 만들고:

```python
def add(a, b):
    result = a + b
    return result

def multiply(a, b):
    result = a * b
    return result

x = add(3, 5)
y = multiply(x, 2)
print(f"최종 결과: {y}")
```

1. 터미널에서 `python3 debug_test.py` 로 실행
2. ▶ 버튼으로 실행
3. `result = a + b` 줄에 중단점 설정 후 `F5`로 실행 → 변수 값 확인

### 실습 2. 디버그로 버그 찾기

아래 코드에 버그가 있다. 디버그 모드로 실행해서 어디서 문제가 생기는지 찾아보자.

```python
def sum_list(numbers):
    total = 0
    for n in numbers:
        total = n   # 버그: += 가 아니라 = 사용
    return total

data = [1, 2, 3, 4, 5]
print(sum_list(data))   # 예상: 15, 실제: ?
```

`total = n` 줄에 중단점을 설정하고 `F10`으로 한 단계씩 실행하며 `total` 값의 변화를 확인한다.

## 자주 하는 실수

| 상황 | 증상 | 해결 방법 |
|------|------|----------|
| ▶ 버튼인데 이전 코드가 실행됨 | 저장 안 된 코드 실행 | `Cmd/Ctrl+S` 저장 후 실행 |
| 디버그 중 변수가 안 보임 | VARIABLES 패널 비어있음 | 중단점이 실행되는 줄에 있는지 확인 |
| F5 눌렀는데 launch.json 요청 | 처음 디버그 실행 | Python 파일 선택 후 실행 |
| ▶ 버튼이 다른 파일 실행 | 포커스가 다른 파일에 있음 | 실행할 파일 탭 클릭 후 ▶ |
