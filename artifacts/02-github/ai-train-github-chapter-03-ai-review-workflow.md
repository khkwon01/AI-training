# ai-train Module 02: GitHub로 작업 정리하고 리뷰받기

## 이 장에서 배우는 것

- GitHub로 작업을 정리하는 기본 흐름
- branch와 pull request가 왜 필요한지
- AI review와 사람 review를 어떻게 함께 사용하는지

## 먼저 쉬운 설명

코딩을 하다 보면 파일이 계속 바뀐다.  
이때 GitHub를 쓰면:

- 무엇을 바꿨는지 기록할 수 있고
- 작업을 나눌 수 있고
- 다른 사람이나 AI에게 검토를 요청할 수 있다

초보자에게 GitHub는 "어려운 협업 도구"가 아니라,  
`내 작업을 정리하고 확인받는 노트`라고 생각하면 이해가 쉽다.

## 핵심 개념

### 1. issue

지금 할 일을 짧게 적어두는 작업 메모다.

예:

- 로그인 버튼 문구 수정
- 파이썬 예제 설명 추가
- 리뷰 체크리스트 보완

### 2. branch

원래 작업과 분리해서 따로 수정하는 작업 공간이다.

### 3. pull request

내가 바꾼 내용을 "검토해 주세요"라고 보여주는 요청이다.

## 흐름 한눈에 보기

처음에는 아래 순서만 기억해도 충분하다.

1. 바꿀 일을 `issue`로 한 줄 적는다
2. 그 일만 처리할 `branch`를 만든다
3. 아주 작은 변경 1개를 수정한다
4. 왜 바꿨는지 적어서 `pull request`를 연다
5. AI review로 빠진 점과 애매한 표현을 먼저 본다
6. 사람 review로 초보자도 이해되는지 마지막 확인을 받는다

즉, GitHub review 흐름은  
`할 일 정리 -> 따로 수정 -> 설명 붙여 공유 -> AI 확인 -> 사람 확인`이다.

## 따라 하기

### 실습 1. 아주 작은 작업 고르기

작업 예시:

- lesson checklist에 review 항목 1개 추가하기
- 안내 문장 1개를 더 쉬운 말로 바꾸기
- 설치 순서 설명 아래에 주의 문장 1개 추가하기

처음에는 "한 번에 5분 안에 설명할 수 있는 작업" 정도가 좋다.

### 실습 2. issue를 짧게 써 보기

예:

```text
제목: checklist 문장을 더 쉽게 수정하기
설명: 초보자가 바로 이해하기 어렵다는 의견이 있어 표현을 단순하게 바꾼다.
```

### 실습 3. branch 이름 정하기

예:

`ai-train-github-checklist-update`

branch 이름은 "무엇을 바꾸는지"가 보이면 충분하다.

### 실습 4. 변경 범위 정하기

처음에는 아래처럼 아주 작게 잡는다.

- 문장 1개 수정
- 체크리스트 항목 1개 추가
- 예시 설명 1개 보완

이렇게 해야 review하는 사람도 빠르게 이해할 수 있다.

### 실습 5. PR 설명 써 보기

아래 내용을 짧게 적는다.

- 무엇을 바꿨는가
- 왜 바꿨는가
- 무엇을 중점적으로 봐 달라는가

예:

```text
목표: 초보자용 review checklist를 더 쉽게 이해되도록 수정
이유: 현재 문장이 조금 추상적이어서 따라 하기 어렵다
리뷰 요청: 문장이 쉬운지, 빠진 항목은 없는지 확인해 주세요
```

### 실습 6. review를 두 번 받기

먼저 AI review에서 아래를 본다.

- 설명이 범위를 벗어나지 않았는가
- 문장이 너무 어렵지 않은가
- 빠진 확인 항목은 없는가

그 다음 사람 review에서 아래를 본다.

- 초보자가 순서대로 따라 할 수 있는가
- 설명이 실제 수업에서 자연스럽게 읽히는가
- AI가 놓친 어색한 표현은 없는가

## AI review와 사람 review

### AI review가 잘하는 것

- 빠르게 전체 내용을 훑기
- 빠진 항목 찾기
- 표현이 애매한 부분 지적하기

### 사람 review가 꼭 필요한 이유

- 초보자가 실제로 이해할 수 있는지 판단
- 설명 순서가 자연스러운지 판단
- 교육 자료로서 충분히 쉬운지 판단

## 자주 하는 실수

- 너무 큰 작업을 한 번에 PR로 올리기
- issue 없이 바로 수정 시작하기
- 왜 바꿨는지 설명하지 않기
- AI review만 보고 끝내기
- 초보자 기준이 아니라 작성자 기준으로만 보기

## 확인 체크리스트

- issue가 한 줄로 설명되는가
- 한 번에 한 가지 작은 작업만 다뤘는가
- branch 이름이 작업 내용과 연결되는가
- PR 설명에 목표와 이유가 들어갔는가
- AI review와 사람 review를 둘 다 생각했는가

## 추가 연습

### 연습 1. 초보자용 작은 수정 고르기

아래 중 GitHub 연습용으로 가장 알맞은 것을 골라 보자.

- 문서 전체 구조를 한 번에 바꾸기
- 체크리스트 문장 1개를 더 쉬운 말로 바꾸기
- 여러 파일의 제목 형식을 모두 다시 맞추기

가장 알맞은 것은 두 번째다.  
이유는 범위가 작고, 무엇이 바뀌는지 바로 설명할 수 있기 때문이다.

### 연습 2. review 요청 문장 써 보기

아래 상황에서 PR 설명 마지막 줄을 직접 써 보자.

- 변경 내용: 설치 안내 아래에 "오타를 먼저 확인하세요" 문장 추가
- 목적: 초보자가 실수 없이 따라오게 하기

예:

```text
리뷰 요청: 초보자 기준에서 이 안내 문장이 실제로 도움이 되는지 확인해 주세요
```

## 교사용 메모

학습자가 GitHub 용어를 외우는지보다,  
`왜 작은 변경으로 나누는지`와 `왜 AI review 뒤에 사람 review가 필요한지`를 설명할 수 있는지 먼저 확인하면 좋다.

3. 초보자 교육 자료는 누가 읽는다고 생각하고 써야 할까?
